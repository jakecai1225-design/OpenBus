# sin UI 布局描述规范

> **用途**：本文件是 sin 软件 UI 布局的唯一权威描述。所有 UI 变更需先修改本文件，
> 经浏览器原型确认后，再进行 Qt 代码实现。
>
> **工作流**：修改本描述 → 渲染 ui-prototype.html 确认 → Qt 代码实现

---

## 1. 窗口总览

```
无边框窗口 (Qt::FramelessWindowHint)
├── MenuBar          — 菜单栏（兼标题栏，可拖拽/双击最大化）
├── LeftDock         — 左侧栏（ActivityBar + SideBar，永久停靠）
├── CenterArea       — 中央编辑区（可拆分标签页）
├── RightDock        — 右侧栏（属性/统计）
├── BottomDock       — 底部栏（终端/输出/问题）
└── StatusBar        — 状态栏
```

### 1.1 窗口属性
- 标题: `sin - CAN/CAN FD 报文分析工具`
- 默认尺寸: 1400 × 900
- 窗口标志: `Qt::Window | Qt::FramelessWindowHint`
- 边缘缩放: 5px 命中区，支持 Aero Snap
- 菜单栏拖拽: 空白区域按住左键拖动窗口
- 菜单栏双击: 切换最大化/还原

### 1.2 设计理念

> **左侧栏 = 入口面板**：只做项目条目的展示和入口，不做过多的折叠。
> 具体的信息，都在自己的标签页内部去设计。
> 点击某个条目，跳转到对应的标签页去。
>
> **中央区 = 工作区**：每个功能模块（Trace、Graphic、DBC、发送、录制）
> 拥有独立的标签页，页面内部包含完整的配置和操作。
>
> **标签页-侧边栏联动**：点击中央标签页时，左侧 ActivityBar 和 SideBar
> 自动切换到对应的入口面板，保持导航上下文一致。反向同理——点击
> 侧边栏条目时，中央也会切换到对应标签页。

### 1.3 面板边界与窗口行为

> 所有 Dock 面板（LeftDock、RightDock、BottomDock、CenterArea）遵循统一的面板交互规范：

- **边界线**：相邻面板之间有明显的边界分割线，分割线可拖拉拖拽，实时调整各面板大小
- **面板操作**：每个面板支持关闭、最大化、最小化；可拖出主窗口分离为独立浮动页面，也可拖回主窗口重新合并
- **一键重置**：面板布局被打乱后，可通过菜单 `视图 → 重置布局` 一键恢复默认排列
- **标签页分离**：中央标签页可拖拽分离出主窗口成为独立窗口，拖回可合并

### 4.5 DBC 详情标签页

点击侧边栏 DBC 文件后，在中央打开 DBC 详情标签页，可以多开，一个dbc对应一个标签页。
采用 Vector CANdb++ Editor 风格布局，左侧分层树展示全部 DBC 对象，右侧上下文敏感详情面板。

```
┌──────────────────────────────────────────────────────────────┐
│ DBC: engine.dbc                                               │
├────────────────────┬─────────────────────────────────────────┤
│ [搜索信号/报文/节点.] │                                         │
├────────────────────┤  (右侧详情面板 — 根据左侧选中项切换)        │
│ ▼ engine.dbc       │                                         │
│   ▼ Network Nodes  │  ┌ Message: EngineStatus (0x123) ────┐  │
│     Engine         │  │ ID: 0x123 (291)  DLC: 8            │  │
│     Brake          │  │ Sender: Engine  Cycle: 10ms        │  │
│     Steering       │  │ Comment: ...                       │  │
│   ▼ Messages       │  ├ Signals ────────────────────────────┤  │
│     0x123 Engine.. │  │ Name       Start Len  Order  Factor │  │
│       EngineRPM    │  │ EngineRPM   0     16   Intel  0.1   │  │
│       ThrottlePos  │  │ ThrottlePos 16    8    Intel  0.4   │  │
│     0x456 BrakeC.. │  │ CoolantTemp 24    8    Intel  1.0   │  │
│       BrakePressure│  └────────────────────────────────────┘  │
│   ▼ Value Tables   │                                         │
│     VT_GearState   │  ┌ Signal: EngineRPM ─────────────────┐  │
│     VT_OBDStatus   │  │ Start Bit: 0    Length: 16         │  │
│                    │  │ Byte Order: Intel  Factor: 0.1     │  │
│                    │  │ Min: 0  Max: 8000  Unit: rpm       │  │
│                    │  │ Receiver: Brake, Steering          │  │
│                    │  ├ Value Table ───────────────────────┤  │
│                    │  │ 0     = Invalid                     │  │
│                    │  │ 1     = Valid                       │  │
│                    │  └────────────────────────────────────┘  │
└────────────────────┴─────────────────────────────────────────┘
  ← 左侧树 30% →       ← 右侧详情 70% →
```

#### 4.5.1 DBC 树形结构 (左侧) — CANdb++ 风格分层
- 顶层: DBC 文件 (Network)
- 二层分类节点:
  - **Network Nodes** — BU_ 段定义的 ECU/节点列表
  - **Messages** — BO_ 段定义的报文列表
    - 三层: 每个报文显示 `0xID  Name`
    - 四层: 该报文下的信号 (SG_)，多路复用信号标注 `[M]`/`[mN]`
  - **Value Tables** — VAL_TABLE_ 段定义的命名值表
- 支持搜索/过滤（匹配信号名、报文名、节点名）
- 右键 Message/Signal → "添加到 Graphic" 选择目标
- 双击 Signal → 发出 signalDoubleClicked 信号

#### 4.5.2 DBC 详情面板 (右侧) — 上下文敏感
右侧使用 QStackedWidget，根据左侧选中项切换页面：

**选中 Message 时：**
- 标题: `Message: Name (0xID)`
- 属性栏: ID(十进制+十六进制) | DLC | Sender | Cycle Time | Send Type | TX Nodes
- Comment (如有)
- Signals 表格: 名称、起始位、长度、字节序(Intel/Motorola)、符号(Signed/Unsigned)、因子、偏移、最小/最大值、单位

**选中 Signal 时：**
- 标题: `Signal: Name (Message: MsgName, 0xID)`
- 属性表 (2列): Name, Start Bit, Bit Length, Byte Order, Value Type, Factor, Offset, Minimum, Maximum, Unit, Receiver, Sender, Multiplexing, Value Table
- Comment (如有)
- Value Table 表格 (如有): 值 → 描述

**选中 Node 时：**
- 标题: `Node: Name`
- Comment (如有)
- TX 报文表: 该节点发送的所有报文 (ID, 名称, DLC)
- RX 信号表: 该节点接收的所有信号 (报文ID, 信号名, 报文名)

**选中 Value Table 时：**
- 标题: `Value Table: Name`
- 值描述表: 值 → 描述

#### 4.5.3 DBC 解析器支持的 DBC 段
| DBC 段 | 说明 |
|--------|------|
| VERSION | 版本信息 |
| BU_ | 网络节点 (ECU) |
| BO_ | 报文定义 |
| SG_ | 信号定义 (含多路复用) |
| CM_ | 注释 (节点/报文/信号) |
| BA_DEF_ / BA_DEF_DEF_ | 属性定义与默认值 |
| BA_ | 属性值 (GenMsgCycleTime, GenMsgSendType 等) |
| VAL_ | 信号内联值表 |
| VAL_TABLE_ | 命名值表 |
| BO_TX_BU_ | 报文发送节点 |
| SIG_VALTYPE_ | 信号值类型 (1=Float, 2=Double) |

#### 4.6.1 发送列表
- 每行为一条待发送报文，支持拖拽调整顺序
- 每行控件: 单独发送 [▶] / 单独停止 [⏹] / 周期 (ms) / 次数 (0=无限)
- 状态列: 发送中 / 停止 / 已完成
- 双击行可进入编辑区修改

#### 4.6.2 工具栏
- [▶ 全部发送]: 按列表顺序和周期发送所有报文
- [⏹ 全部停止]: 停止所有发送中的报文
- [+ 从DBC导入]: 从已加载的 DBC 中选择报文/信号，自动填充 ID 和 DLC
- [📂 从文件回放]: 加载 .sin/.asc 录制文件，按时间戳回放发送
- [🗑 清空列表]: 清除所有待发送报文

#### 4.6.3 编辑区
- 手动输入 ID、DLC、数据字节
- 周期: 发送间隔 (ms)，0=单次
- 次数: 发送次数，0=无限循环
- 从 DBC 选择报文后可自动填充名称、ID、DLC
- [添加到列表]: 将编辑的报文加入发送列表
- [发送单帧]: 不加入列表，立即发送一次

## 11. 第三方库与开发指引

> **原则**：优先引入轻量级 C++ 开源库，避免重复造轮子。库应尽量精简，不引入臃肿依赖。

| 用途 | 候选库 | 说明 |
|------|--------|------|
| DBC 解析 | dbcppp (参考) | 已下载至 `third_party/dbcppp_src/`，参考其语法规则和位遍历算法，不直接编译 |
| 曲线绘制 | QCustomPlot / KDChart | 轻量级 Qt 绘图库，用于 Graphic 标签页波形渲染 |
| 数据列表 | Qt 自带 QTableView | 无需额外依赖 |
| 时序数据 | Qt 自带 QStandardItemModel | 无需额外依赖 |

- 新增第三方库需放入 `third_party/` 目录，并在 CMakeLists.txt 中按需链接
- 参考库（不直接编译）仅作为算法和设计参考，不纳入构建系统
