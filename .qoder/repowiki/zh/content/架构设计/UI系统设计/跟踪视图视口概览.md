## 简介
本文件聚焦"跟踪视图视口概览"能力，围绕 CANoe 风格的固定行数视窗与缩略图导航展开。该能力通过模型链将数据源、过滤层与视窗层解耦，使界面在海量帧数据下仍保持流畅交互：左侧为可视化的数据密度缩略图（可拖拽/点击跳转），右侧为报文列表；底部提供帧结构与信号解析面板。整体设计兼顾高性能渲染与直观导航。

**最新更新**：显著增强了跟踪视图的分析能力，新增了选中帧统计和差异对比功能，改进了 I/O 图集成和字体大小调整机制，采用了基于定时器的拖拽方式（~60fps），使用全局鼠标位置跟踪，提升了交互性能和用户体验。**最新改进**：视口概览现在始终显示缩略图视图，解决了清除跟踪后概览有时保持隐藏的问题，并通过SignalRelay实现了跨DLL的视口变化通知。

## 项目结构
跟踪视图相关代码主要分布在 UI 与 Models 两层：
- UI 层：TraceView、ViewportOverview、TraceTab、FilterBar、TraceStatisticsWidget、TraceDiffWidget 等负责交互与布局
- Models 层：CanTraceModel、CanFilterProxyModel、ViewportProxyModel 负责数据、过滤与视窗映射
- 数据载体：CanFrame 定义帧结构与时序信息
- 通信层：SignalRelay 提供跨DLL的信号转发机制

## 核心组件
- TraceView：CANoe/Wireshark 风格报文列表视图，支持列筛选、排序、选中保持、导航（GoTo/Find/Next Same ID）、字体缩放（Ctrl++/Ctrl+-/Ctrl+0）
- ViewportProxyModel：在过滤模型之上叠加"固定行数视窗"，仅暴露当前视窗内的行，外部滚动条控制视窗在全量数据中的位置
- CanFilterProxyModel：基于 FilterEngine 的主表达式 + 按列子过滤器，支持时间戳显示模式切换与分组统计
- CanTraceModel：高性能追踪数据模型，环形缓冲存储、延迟格式化、可见行缓存、批量提交刷新
- **ViewportOverview**：左侧缩略图控件，绘制 Rx/Tx 密度分布，高亮当前视窗区域，**采用基于定时器的拖拽机制（~60fps）**，支持拖拽/点击/滚轮移动，**现始终显示**
- **TraceStatisticsWidget**：选中帧统计分析视图，支持时间统计（帧数、时间跨度、相邻帧Δt统计）和信号统计（DBC解码后的min/max/avg/σ/首末值）
- **TraceDiffWidget**：选中帧差异对比视图，支持概览对比、字节级Hex对照、信号级差异分析，默认仅显示变化项
- **SignalRelay**：跨DLL信号转发器，解决MinGW环境下跨DLL信号连接问题
- TraceTab：组合上述组件，构建三栏布局（过滤栏+工具条、报文列表、帧结构与信号解析）

## 架构总览
模型链采用三层代理：CanTraceModel → CanFilterProxyModel → ViewportProxyModel → QTableView。ViewportProxyModel 将源模型的任意连续区间映射到固定大小的视窗内，QTableView 的内置滚动条仅在该视窗内滚动；外部通过 ViewportOverview 或 API 调整视窗起始位置，实现"大数据集下的稳定视图"。**新增的统计和差异分析组件通过 TraceTab 的 onSelectionChanged 方法接收选中帧集合，进行实时分析和展示**。

**重要改进**：通过SignalRelay实现了跨DLL的信号连接，确保ViewportProxyModel的viewportChanged信号能够正确传递到TraceTab，从而更新缩略图显示。

### TraceStatisticsWidget（选中帧统计视图）

**新增组件**：提供选中帧的全面统计分析功能

- 职责：对选中的帧集合进行时间维度和信号维度的统计分析
- 关键特性：
  - **时间统计**：帧数 N、时间跨度、相邻帧 Δt 的 min/max/avg/σ（标准差）

  - **字节统计**：未加载 DBC 时按字节位置统计数值特征
  - **性能优化**：100ms 防抖重算，MaxFrames=10000 上限截断
- 数据源：TraceView 当前选中行集合，内部按时间排序后处理

### ViewportOverview（视窗缩略图控件）

**重大更新**：显著改进了拖拽机制，采用基于定时器的处理方式，**现始终显示缩略图**

- 职责：可视化全部数据的 Rx/Tx 密度，高亮当前视窗区域，支持拖拽、点击跳转、滚轮移动
- **新的拖拽机制**：
  - **定时器驱动**：使用 QTimer 以 ~60fps 频率处理拖拽事件（16ms间隔）
  - **全局鼠标跟踪**：通过 QCursor::pos() 获取全局鼠标坐标，不依赖 widget 内部事件传递
  - **增强的光标管理**：拖拽时显示 SizeVerCursor，释放时恢复 ArrowCursor
  - **健壮的拖拽状态管理**：防止 mouseReleaseEvent 未送达的情况
- **渲染优化**：
  - 像素级采样：每行像素对应 total/h 行，采样统计 Rx/Tx 比例，绘制水平密度条
  - 缓存机制：Pixmap 缓存密度图，仅在尺寸/数据变化时重建，高频帧到达时通过定时器节流
  - **始终显示**：移除了基于数据量的隐藏逻辑，即使数据为空也显示空底
- 交互逻辑：
  - mousePressEvent：判断是否在视窗区域内（拖拽）或外（跳转）
  - **onDragTimer**：定时器回调函数，处理实际的拖拽逻辑和视窗位置更新
  - wheelEvent：以 1/4 视窗步长滚动

### SignalRelay（跨DLL信号转发器）

**新增组件**：解决MinGW环境下跨DLL信号连接问题

- 职责：提供字符串信号到lambda/std::function的桥接，解决跨DLL场景下的信号连接失败问题
- 关键特性：
  - **多签名支持**：支持多种参数签名的信号转发
  - **类型安全**：编译时类型检查，运行时动态调用
  - **轻量级**：最小开销的信号转发机制
  - **生命周期管理**：由父对象管理，自动清理
- 应用场景：
  - ViewportProxyModel的viewportChanged信号转发
  - 其他跨DLL的信号通信场景

## 性能考量
- 视窗限制：ViewportProxyModel 固定视窗大小，减少 QTableView 渲染压力
- 增量更新：setViewportStart 根据行数变化选择 dataChanged/insert/remove/reset，避免全量刷新
- 密度缓存：ViewportOverview 使用 QPixmap 缓存密度图，定时器节流重建
- 行缓存：CanTraceModel 对可见行范围进行缓存与淘汰，降低格式化开销
- 批量提交：CanTraceModel 支持暂停刷新与一次性 flush，降低高频帧时的 UI 抖动
- 采样渲染：ViewportOverview 每像素行采样固定数量帧，平衡精度与性能
- **拖拽性能优化**：采用定时器驱动的拖拽机制（~60fps），避免频繁的事件处理开销，提升响应速度和稳定性
- **统计分析优化**：TraceStatisticsWidget 和 TraceDiffWidget 均采用 100ms 防抖机制，避免频繁重算
- **字体缩放优化**：TraceView 字体大小变化时仅更新必要属性，避免全量重绘
- **跨DLL通信优化**：SignalRelay提供轻量级的信号转发机制，避免复杂的跨模块通信开销
- **始终显示优化**：移除数据量检查逻辑，简化渲染流程，提升响应速度

## 故障排查指南
- 视窗未更新：检查 ViewportOverview::markCacheDirty 是否被调用，确认 m_cacheDirty 标志与定时器状态
- **拖拽无效**：确认 m_dragging 状态正确，检查 m_dragTimer 是否启动，验证全局鼠标位置获取是否正常
- **拖拽卡顿**：检查定时器间隔设置（应为16ms），确认 onDragTimer 函数执行效率
- **光标异常**：确认 mouseReleaseEvent 中光标恢复逻辑，检查 hideEvent 中的清理逻辑
- **统计组件无响应**：检查 TraceTab::onSelectionChanged 是否正确调用 setFrames 方法，确认 DbcManager 已正确设置
- **差异对比异常**：确认选中帧数量≥2，检查 DBC 管理器是否正确配置，验证首末帧时间排序逻辑
- **字体缩放无效**：检查 applyFontSize 方法中的字体设置逻辑，确认 QSettings 读写正常
- **跨DLL信号连接失败**：确认SignalRelay正确初始化，检查SIGNAL/SLOT连接是否成功
- **缩略图不显示**：确认updateViewportOverview方法被正确调用，检查m_viewportOverview是否存在
- **选中丢失**：过滤/排序前调用 pinSelection，变更后调用 restoreSelection，确保选中行映射正确
- **自动跟随异常**：确认 autoScrollEnabled 与 m_autoScrollViewport 状态，以及 framesCommitted 信号连接
- **滚动不同步**：视窗切换后重置 verticalScrollBar 值为 0，避免旧滚动位置残留

## 结论
该实现通过"数据模型—过滤层—视窗层"的分层架构，配合缩略图导航与高密度渲染优化，提供了高效、直观的 CAN 报文跟踪体验。**最新的增强功能**包括：新增的 TraceStatisticsWidget 和 TraceDiffWidget 组件提供了强大的选中帧分析能力，改进的 I/O 图集成提供了直观的流量可视化，增强的字体大小调整功能提升了用户体验。**基于定时器的拖拽机制**（~60fps）通过全局鼠标位置跟踪和增强的事件处理，显著提升了拖拽操作的流畅性和可靠性。**最重要的改进**是视口概览现在始终显示缩略图视图，解决了清除跟踪后概览有时保持隐藏的问题，并通过SignalRelay实现了可靠的跨DLL信号通信。ViewportProxyModel 保证大流量场景下的稳定视图，ViewportOverview 提供直观的宏观导航，TraceView 提供细粒度操作能力，新增的分析组件提供深度数据分析能力，SignalRelay确保跨模块通信的可靠性。五者协同，形成完整的跟踪视图视口解决方案。
