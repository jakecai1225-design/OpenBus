项目采用「壳 + 业务 DLL + 原生驱动插件 + Python 工具插件」的分层架构：
- 入口 `src/main.cpp` 初始化 QApplication、日志、配置与会话，通过 `ModuleRegistry` 按名称注册 market/transceive/dbc/flow/trace/graphic 六个业务模块，每个模块以独立 DLL 暴露唯一 C 工厂函数 `openbus_create<Xxx>Module()`，由 `src/core/module/imodule.h` 中的 `IBusinessModule` 接口约束，实现 UI 与核心逻辑解耦。
- 核心层 `src/core/` 提供数据模型（`CanFrame`、`BusMessage`）、设备抽象（`candevicemanager` + 各厂商 `candevice_*`）、文件 I/O（`canfileio/` 支持 BLF/ASC/CSV/PCAP/TRC）、DBC 管理（dbcppp）、协议解析、过滤引擎、回放/录制/模拟器等；`src/models/` 提供 Trace 表格模型与代理模型；`src/ui/` 为 Qt Widgets 界面（MainWindow、TraceView、GraphicView、各 Tab）。
- 驱动插件位于 `drivers/<id>/`（zlg/peak/kvaser/slcan/candle），每个子目录含 `driver.json` 清单与 `*_driver_plugin.{h,cpp}`，通过 QPluginLoader 在主进程内热加载，ABI 契约与主程序同 Qt/编译器。
- Python 插件位于 `plugins/<name>/`，每个插件自包含 `main.py`、`plugin.json` 与可选共享库（`_shared/dbcparse.py`、`isotp_client.py`），由 `src/core/plugin/pluginmanager.h` 管理的 `PluginHost` 启动独立 Python 宿主进程，通过 JSON-RPC 双向通信，支持帧订阅制推送、命令注册、文件转换 Job、DBC 会话等能力。
- 构建系统使用顶层 `CMakeLists.txt` 聚合 `src/`、`drivers/`、`tests/`，第三方依赖集中声明于 `third_party/Dependencies.cmake`；打包与安装由 `installer/openbus.iss` 与 `scripts/build.py`、`package.py`、`make_market.py`、`driver_tool.py`、`plugin_tool.py` 等脚本协同完成。
