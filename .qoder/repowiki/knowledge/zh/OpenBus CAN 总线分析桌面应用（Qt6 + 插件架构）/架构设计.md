项目以 CMake 构建（C++17 + Qt6 Widgets），入口 `src/main.cpp` 初始化日志、配置与会话后启动 `MainWindow`。核心分层清晰：
- `src/core/`：纯业务内核，按职责划分为 `canfileio/`（ASC/BLF/CSV/PCAP/TRC 读写）、`dbc/`（ARXML/DBC 导入导出）、`driver/`（驱动注册表与厂商 DLL 动态加载）、`file_import/`（文件导入器工厂）、`plugin/`（Python 插件宿主 `PluginHost`，通过 QProcess 运行 `scripts/sin_host.py` 并以 newline-delimited JSON-RPC 通信，支持崩溃指数退避重启）。
- `src/ui/`：Qt 界面层，包含主窗口、各 Tab（记录/回放/信号发送/离线分析/市场等）、侧边栏、图形视图（QCustomPlot）及主题管理。
- `src/models/`：基于 `QAbstractTableModel` 的 Trace 数据模型与代理模型，配合 `ViewportProxy` 实现大数据量视口裁剪。
- `src/utils/`：环形缓冲、消息队列、SVG 图标等通用工具。
- `drivers/<vendor>/`：每个厂商一个独立 CMake 子工程，编译为 `.dll` 插件，实现 `CanDriverPlugin` 接口并通过 `Q_PLUGIN_METADATA` 暴露；由 `core/driver/driverregistry` 在运行时扫描并加载，ABI 契约限定仅传 POD/Qt 值类型与 `ICanDevice*` 裸指针。
- `plugins/<name>/`：Python 插件，每个含 `plugin.json` 描述元信息、`main.py` 入口，通过 SDK `sdk/sin/` 提供的 Python API 与宿主进程交互。
- `resources/`：Qt Resource (`resources.qrc`) 集中管理 SVG 图标与 QSS 样式；`UI/` 提供 HTML+JS 原型页面。
依赖方向单向：ui → core → utils/third_party；drivers 与 plugins 通过 ABI/JSON-RPC 边界与主程序解耦。
