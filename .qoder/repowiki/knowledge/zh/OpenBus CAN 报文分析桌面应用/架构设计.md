顶层工程以 CMake 为入口（CMakeLists.txt），将 src/ 下的 Qt 主程序作为单一可执行 openbus 构建；src/main.cpp 在启动时依次初始化日志、AppConfig、SessionManager、ThemeManager 并创建 MainWindow，MainWindow 再组合 core/ 中的设备管理、DBC、文件导入、记录/回放、过滤引擎等模块。

跨子模块的协作契约集中在两处：
- 驱动层：driver/kerneldlls 提供各厂商 CAN 硬件 DLL（ZLG、Kvaser、Peak 等），src/core/candevice* 与 src/core/driver/ 通过统一的 candriverplugin.h 接口动态加载这些 DLL，实现多硬件抽象。
- 插件层：src/core/plugin/ 实现 PluginManager/PluginHost/PluginConvertJob，扫描 plugins/*/plugin.json 发现 Python 插件，通过 scripts/sin_host.py 启动独立 Python 进程，并以 JSON-RPC 风格消息与 sdk/sin/* 暴露的 output/frames/commands/workspace/signals/files/dbc 等 API 通信；plugins/ 下的 blf-converter、bus-statistics、canopen-explorer、dbc-tool、uds-diagnostic 均遵循同一 plugin.json + main.py 约定。

resources/ 下的 .qrc 资源与 UI/ 下的 HTML+JS 原型由 Qt RCC 编译进二进制，供 ui/ 面板与主题系统使用；scripts/build.py、scripts/driver_tool.py、scripts/plugin_tool.py 是根级构建与工具入口，统一协调 C++ 编译、Python SDK 分发与插件打包。
