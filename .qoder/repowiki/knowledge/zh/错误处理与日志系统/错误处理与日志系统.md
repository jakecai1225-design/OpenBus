本仓库的错误处理采用分层策略：核心 I/O 和解析层使用 C++ 异常加 spdlog 结构化日志，UI 层通过状态栏标签和 qWarning/qDebug 反馈，过滤引擎则返回布尔值与 errorString() 字符串。没有统一的错误类型或返回值编码体系。

### 1. 使用的系统与工具
- spdlog：作为全局日志后端，提供控制台彩色输出与滚动文件（5MB × 3 个文件）双 sink，按 [时间] [级别] [模块] 消息格式输出。
- Qt 调试宏：qWarning()、qDebug() 用于 UI 侧快速诊断；std::cerr 在少数底层 I/O 失败时直接打印。
- C++ 异常：第三方库（nlohmann json、Vector BLF）抛出的 json::parse_error、std::exception 被 try/catch 捕获并转为日志。
- 无统一错误类型：未定义自定义 exception 类或错误码枚举，错误信息以字符串形式在调用栈上传播或直接记录。

### 2. 关键文件与位置
- src/core/logging.h / logging.cpp：日志系统初始化、SIN_LOG_* 宏、默认 logger 获取。
- src/core/filter_engine.h / filter_engine.cpp：过滤表达式编译失败时通过 errorString() 返回人类可读错误。
- src/core/appconfig.cpp：JSON 配置解析失败回退到默认值，并用 spdlog::error 记录。
- src/core/canfileio/blf.cpp：BLF 读写异常被捕获后打印到 std::cerr 并返回 false。
- src/core/file_import/*.cpp：ASC/BLF 导入失败使用 qWarning() 提示。
- src/ui/mainwindow.h：状态栏包含 m_errorLabel 用于显示错误信息。

### 3. 架构与约定
- I/O 层：所有可能失败的函数（open/read/write）返回 bool，失败时内部用 spdlog::error 或 std::cerr 记录原因，调用方检查返回值决定是否继续。
- 解析层：FilterEngine 的 compile() 返回 bool，失败时 errorString() 提供具体语法错误描述；其他解析器（如 ASC/BLF importer）直接抛出异常由上层 catch。
- UI 层：不向上抛出异常，而是通过 qWarning() 输出警告并在状态栏 m_errorLabel 展示给用户。
- 配置层：AppConfig 对 JSON 解析异常静默回退到默认配置，保证应用可启动。

### 4. 约定与约束
- 所有日志必须通过 SIN_LOG_* 宏（带模块 tag），禁止直接使用 qDebug 记录业务错误（仅允许用于调试输出）。
- 文件操作失败必须记录 spdlog::error 并返回 false，不得吞掉异常。
- 过滤表达式编译失败必须设置 errorMsg 以便 errorString() 返回。
- 未捕获的异常应通过 catch (...) 兜底，避免程序崩溃。
