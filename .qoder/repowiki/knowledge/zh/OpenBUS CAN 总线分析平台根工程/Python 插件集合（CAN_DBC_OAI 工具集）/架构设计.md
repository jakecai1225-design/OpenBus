插件以独立目录为单位组织，每个插件包含 main.py（入口）、plugin.json（元数据与命令贡献）、icon.svg（图标），部分插件附带 dbcparse.py 或 isotp_client.py 等本地依赖。
- 共享库：_shared/dbcparse.py 实现 DBC 文件的解析、信号位域提取/写入（Intel/Motorola 字节序）、Message/Signal/DbcFile 模型；_shared/isotp_client.py 提供 ISO-TP 客户端封装，被 uds-scan、uds-batch、uds-security-audit 等复用。
- 插件契约：plugin.json 统一声明 name/version/main/icon/activationEvents/contributes.commands，由宿主根据 activationEvents 触发加载；main.py 通过 import sin 接入宿主框架，并可选 import dbcparse 使用 DBC 能力。
- 典型模式：DBC 类插件（can-dashboard、can-frame-generator、can-id-scanner、can-simulator、dbc-codegen、dbc-diff、dbc-exporter、dbc-lint、dbc-merge、trigger-logger）各自在目录下复制一份 dbcparse.py 副本以避免版本冲突；通信协议类插件（iso-tp-monitor、isobus-monitor、xcp-monitor、j1939-analyzer、e2e-checksum、frame-compare、log-toolkit、nmea2000-decoder、obd2-scanner、autosar-nm-monitor、gbt27930-monitor）直接依赖宿主提供的帧流接口。
- OAI 子模块：oai/workflow_engine.py 基于 LangGraph StateGraph 构建意图分类→MCP 工具调用→响应格式化的状态机节点；mcp_servers/ 提供 cantrace_stream_server、dbc_database_server、filesystem_server 三个 MCP 服务器；langchain_workflow_init.py 作为工作流初始化入口。
- 依赖方向：插件 → _shared/*（可选）→ 宿主 sin 框架；插件之间相互独立，无横向依赖。
