模块由两个子目录组成：scripts/ 是面向开发者的命令行入口，third_party/ 是静态嵌入的第三方源码及 CMake 集成层。
- scripts/build.py 是核心构建编排器，通过 argparse 子命令（configure/build/run/debug/clean/rebuild/deploy/all/test/status/open）封装 CMake 配置、编译、windeployqt 部署、ctest 测试流程；Environment 类集中发现 Qt/MinGW/CMake/Ninja 路径并注入 PATH，cmd_* 函数按顺序调用 subprocess 执行工具链。
- scripts/build.ps1 是 build.py 的 PowerShell 等价实现，提供相同命令集但使用原生 PowerShell 语法，便于在 Windows 环境下直接双击或从 VS Code 任务调用。
- scripts/ 下大量 .bat/.ps1 文件围绕 Windows GUI 窗口问题展开：quick_start.bat、test_window.bat、window_test.bat、diagnose_window_issue.bat、detailed_window_debug.bat、final_diagnostic.bat、apply_window_fix.bat、fix_all_chinese.bat 构成一套“启动→验证→诊断→修复”的窗口问题排查流水线；gdb_openbus.gdb + gdb_commands.txt + run_gdb.bat + gdb_debug.ps1 + debug_frameless.ps1 提供 GDB 断点与 frameless 窗口调试能力；test_openbus*.ps1/.bat 系列负责 ctest 与插件加载日志采集。
- third_party/ 以源码形式内嵌 spdlog、nlohmann_json、pugixml、qcustomplot、concurrentqueue、vector_blf、dbcppp/dbcppp_src，并通过 Dependencies.cmake 暴露 INTERFACE IMPORTED 目标（spdlog）、静态库（qcustomplot）、add_subdirectory（vector_blf）等方式供主工程引用；third_party/scripts/shell_client.py 为独立辅助脚本。
- 依赖方向单向：scripts/ 仅调用外部工具（cmake.exe、g++.exe、windeployqt.exe、gdb.exe、ctest.exe），不依赖项目源码；third_party/ 仅被主工程 CMake 包含，不被 scripts/ 引用。
