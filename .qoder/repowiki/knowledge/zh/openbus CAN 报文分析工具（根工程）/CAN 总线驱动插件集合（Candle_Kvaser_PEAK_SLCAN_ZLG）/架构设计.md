模块以 `drivers/<vendor>/` 为单位组织每个 CAN 适配器族（candle、kvaser、peak、slcan、zlg），每个子目录包含一个 Qt 插件 target、对应的 `driver.json` 元数据以及可选的 vendor SDK 资源。
- 顶层 `drivers/CMakeLists.txt` 通过 `add_subdirectory` 聚合各 vendor，并定义 `deploy_driver_manifest()` CMake 函数：在 POST_BUILD 阶段将 `driver.json` 复制到目标 DLL 同目录，使构建产物直接匹配运行时 `DriverRegistry` 扫描的 `<exe>/drivers/<id>/` 布局。
- 每个插件通过 `qt_add_plugin()` 生成 `.dll`，并在 `target_sources` 中显式引入 `src/core/candevice_<vendor>.h/.cpp` 后端源码（如 `CanDeviceCandle`、`CanDeviceZLG`），从而与主程序共享同一份实现但作为独立插件加载，便于后续迁移到纯外置模式。
- 插件类继承 `QObject` + `CanDriverPlugin` 接口，使用 `Q_PLUGIN_METADATA(IID "com.sin.openbus.CanDriverPlugin/1.0" FILE "driver.json")` 声明 Qt 插件元数据，由主程序通过 `QPluginLoader` 动态发现与加载。
- `driver.json` 描述设备能力（`busType=can`、`canFd`、`hasHwTimestamp`、`vid/pid`、`channels`）及 `vendorSdk` 依赖（如 candle 的 `libusb-1.0.dll` 标记为 `bundled: false`，需运行脚本下载）。
- `driver/zlg/` 下附带 ZLG 厂商 SDK（`zlgcan.dll`、`zlgcan.h`、`zlgcan.lib`）及大量设备 XML 配置与 `kerneldlls/` 下的 PEAK/ZLG 原生 DLL，供 zlg 插件在运行时加载；其他 vendor 仅依赖系统或外部库。
- 依赖方向单向：插件 → `src/core` 后端抽象 → 厂商 SDK / 系统 API；插件之间互不依赖。
