脚本目录按职责划分为五类独立可执行 Python 脚本，彼此通过命令行子进程调用协作：
- 构建编排：`build.py` 是入口，封装 `Environment`（探测 Qt/MinGW/CMake/Ninja）、`cmd_configure/build/run/debug/clean/rebuild/deploy/all/status/test/open` 等子命令，统一通过 `subprocess.run` 调用 CMake/Ninja/GDB/windeployqt；支持多构建目录（`--build-dir build-dev`）与增量 reconfigure 检测。
- 发布流水线：`package.py` 串联 8 步（Release 构建→windeployqt→staging 白名单组装→Python 运行时精简捆绑→附加文件→objdump import 校验→体积报告→zip/Inno Setup 输出），复用 `build.py` 子进程并注入 `SIN_QT_DIR/SIN_MINGW_DIR/SIN_CMAKE_DIR` 环境变量。
- 包格式工具：`driver_tool.py`（.odp ZIP + CHECKSUMS.sha256）与 `plugin_tool.py`（.opk ZIP）提供 pack/install/uninstall/validate 四命令，输出单行 JSON 供 C++ 侧 QProcess 解析。
- 市场生成：`make_market.py` 扫描 `drivers/*/driver.json` 与 `plugins/*/plugin.json`，调用 driver_tool/plugin_tool 打包后生成 schema v2 的 `market.json`（含 drivers[] 与 plugins[]）。
- 宿主与辅助：`sin_host.py` 作为插件运行宿主，通过 stdin/stdout JSON-RPC 2.0 与主程序通信；`download_libusb.py` 从 PyPI wheel 提取 x64 libusb-1.0.dll；`measure_build.py` 解析 `.ninja_log` 产出构建基线表并追加到 `doc/构建基线.md`。
依赖方向单向：package/make_market → driver_tool/plugin_tool → 文件系统；measure_build 直接 import build 模块复用常量。
