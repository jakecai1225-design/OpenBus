- 每个测试套件（B1~B8）编译为独立可执行进程（test_canfileio、test_filterengine、test_tracecore、test_dbc、test_sim_rec_play、test_market_driver、test_project、test_protocol），通过 CMake 函数 `openbus_add_test` 统一注册，确保 core 层全局单例（DbcManager/PluginManager 等）进程级隔离。
- 所有 L1 测试链接共享库 `openbus_data`（提供 core/models/utils 及 spdlog/nlohmann/concurrentqueue 头路径）和 `Qt6::Test`，并通过 `SIN_SOURCE_DIR` 宏定位根目录下的 `test/resources/` 样本数据。
- L2 UI 测试 `test_ui_offscreen` 单独用 `qt_add_executable` 构建，链接壳 UI 静态库 `openbus_ui` 及四个业务模块导入库（openbus_market/openbus_transceive/openbus_dbc/openbus_flow/openbus_trace/openbus_graphic），以 `QT_QPA_PLATFORM=offscreen` 无头模式复用真实 MainWindow 初始化链。
- 顶层 `add_custom_target(tests)` 聚合全部测试目标，供 build.py test 调用，避免触发主程序重链。
- 测试用例通过 doc/测试验收方案.md 中的需求编号（TC-xx、DB-xx、TF-xx、SIM-xx、MKT-xx、PRJ-xx）进行追溯映射，断言分为“真实样本自洽性不变量”和“自构造数据精确值断言”两类。
