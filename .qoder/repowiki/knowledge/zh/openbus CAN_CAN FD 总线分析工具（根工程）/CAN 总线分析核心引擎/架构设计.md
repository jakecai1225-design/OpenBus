代码按 CMake 目标划分为三层：`openbus_core`（core/models/utils）为静态库，承载数据模型 `CanFrame`、设备抽象 `ICanDevice`、录制/回放/模拟器 (`recorder`, `player`, `cansimulator`)、DBC/ARXML 管理 (`dbcmanager`, `dbc_adapter`, `arxml_importer/exporter`)、文件 I/O (`canfileio/*` 支持 ASC/BLF/CSV/PCAP/TRC)、过滤引擎 (`filter_engine`, `logsplitter`)、配置与会话 (`appconfig`, `sessionmanager`, `projectmanager`)；`openbus_ui`（ui/*）为依赖 core 的界面库，包含主窗口、TraceView、GraphicView、各功能 Tab 及主题/侧边栏等组件；顶层 `main.cpp` 通过 `QApplication` 启动并初始化日志、配置、会话后创建 `MainWindow`。

关键边界与依赖方向：
- 设备层通过 `driver/candriverplugin.h` 定义的 `CanDriverPlugin` Qt 插件接口（`Q_DECLARE_INTERFACE` + `Q_PLUGIN_METADATA`）实现厂商驱动热插拔，由 `driverregistry` 加载，`candevicemanager` 统一封装为 `Simulator` 或真实硬件，对外暴露与 `CanSimulator` 一致的信号接口，使 UI 可无缝切换。
- 插件系统通过 `plugin/pluginmanager` 发现、激活 Python 宿主进程（`sin_host.py`），经 `pluginhost` 进行 JSON-RPC 风格消息分发，支持帧转发、命令执行、DBC 会话与文件转换 Job。
- 数据流单向：设备/文件 → `CanFrame` → `filter_engine`/`logsplitter` → `models/cantracemodel` → UI 视图；录制路径反向写入 BLF/ASC/CSV。
- 构建期通过 PCH 将 core 与 ui 解耦，UI 修改不触发 core 重编译；第三方依赖（spdlog、nlohmann_json、concurrentqueue、pugixml、zlib/vector_blf）以可选 target 形式链接。
