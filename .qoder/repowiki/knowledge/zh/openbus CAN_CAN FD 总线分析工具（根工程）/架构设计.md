工程以 CMake 3.21+ 构建，C++17 + Qt6（Widgets/PrintSupport/Svg/Network），入口 `src/main.cpp` 初始化 QApplication、日志、配置与会话后，通过 `ModuleRegistry` 按模块名（market/transceive/dbc/flow/trace/graphic）调用各业务 DLL 导出的 `openbus_createXxxModule()` C 工厂函数注册 UI 模块，实现主程序与业务模块解耦。

核心分层：
- `src/core/`：领域内核（CAN 设备抽象 `candevice*`、驱动注册 `driverregistry`、DBC 解析、协议适配器、文件 I/O、播放器/录制器、会话/项目/过滤引擎等）。
- `src/ui/`：Qt 界面层，含 MainWindow 及多个 Tab（Trace/Graphic/Playback/Record/SignalSend/OfflineAnalysis/Market/Settings 等），通过 `IModule` 接口与 core 交互。
- `src/models/`：Trace 数据模型与代理模型（`CanTraceModel`/`CanTraceProxyModel`/`ViewportProxy`）。
- `drivers/<vendor>/`：厂商硬件驱动以独立 CMake 子目录产出 `.dll`，由 `DriverRegistry` 热加载，遵循统一 `driver.json` 清单。
- `plugins/<name>/`：Python 插件（main.py + plugin.json），通过共享 SDK `sdk/sin/` 与主进程通信，支持 `.opk` 打包安装。
- `third_party/`：dbcppp、spdlog、qcustomplot、vector_blf、nlohmann_json、pugixml 等静态依赖。
- `scripts/`：构建脚本（build.py）、包管理（package.py、make_market.py、plugin_tool.py、driver_tool.py）与 E2E 测试用例。
- `UI/`、`resources/`、`data/`：前端原型、QRC 资源与示例 DBC/BLF/ASC 数据。

依赖方向严格自顶向下：ui → core → third_party；drivers/plugins 通过运行时动态加载，不反向依赖主程序源码。
