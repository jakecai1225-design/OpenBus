- 每个业务功能域封装为独立的共享 DLL，并在 `src/CMakeLists.txt` 中通过 `add_library` 声明，同时暴露统一的 C 工厂函数（如 `openbus_createXxxModule()`）供壳通过 `ModuleRegistry` 动态加载。
- 核心单例（AppConfig、DbcManager、PluginManager、ThemeManager、ModuleRegistry 等）集中放在 `openbus_data` 共享库中，保证全进程唯一实例，业务 DLL 通过链接该库间接访问。
- 每个业务 DLL 在 CMake 中使用 `target_precompile_headers` 显式列出所依赖的 Qt 头集合，以缩短编译时间并避免隐式包含。
- 驱动插件遵循 `drivers/<id>/` 目录结构，每个厂商提供 `driver.json` 描述元数据、`*_driver_plugin.cpp/.h` 实现 `Candriverplugin` 接口，并通过独立 `CMakeLists.txt` 编译为 DLL。
- Python 插件统一采用 `plugin.json` 清单 + `main.py` 入口 + `icon.svg` 图标 + 可选 `__pycache__/` 缓存的结构，共享工具（dbcparse、isotp_client）集中在 `plugins/_shared/`。
- UI 组件按职责拆分到 `src/ui/` 下对应子目录（panels/tools/graphic 等），并通过 `mainwindow_*` 部分实现文件（setup/chrome/actions/frameflow/pages/project/dialogs）分阶段装配，避免单文件膨胀。
