# openbus Trace 页面需求清单

> **版本**: v2.0  
> **日期**: 2026-08-14  
> **范围**: Trace 标签页功能完善与增强  
> **对标产品**: CANoe (Vector)、Wireshark  

---

## 1. 背景与目标

Trace 页面是 openbus 的核心功能页面，承担 CAN/CAN FD 报文的实时列表显示、过滤、导航、标记与解析任务。  
当前完成度约 **65%**，核心数据流已贯通，但与 CANoe / Wireshark 相比仍有若干功能缺口。

本文档梳理 Trace 页面全部功能点，标注已实现/未实现状态，并明确 **下一步实施需求**（12 项）与备选需求（15 项）。

### S04：完整 Hex Dump 视图（Offset + Hex + ASCII）

| 属性 | 内容 |
|------|------|
| **原编号** | REQ-T02 |
| **来源** | Wireshark Packet Bytes |
| **价值** | 专业级原始数据查看，支持 Offset 定位和 ASCII 对照 |
| **难度** | 低 |
| **预计工时** | 1-2 天 |
| **涉及文件** | `traceview.h/cpp`（FrameInfoWidget） |

**需求描述**：

- 将 FrameInfoWidget 的 Hex 显示从单行扩展为多行 Hex Dump 格式：

```
Offset  Hex                                         ASCII
0000    01 02 03 04 05 06 07 08  09 0A 0B 0C 0D 0E 0F 10    ................
0010    11 12 13 14                                       ....
```

- 每行 16 字节，Offset 列 4 位十六进制
- 中间为 Hex 列，空格分隔，8 字节后额外空格分组
- 右侧为 ASCII 列，不可打印字符显示为 `.`
- 数据不足 16 字节时右侧补空格对齐
- CAN FD 帧 64 字节时自动多行显示

**验收标准**：
1. 选中任意帧，帧结构面板显示完整 Hex Dump
2. ASCII 列正确显示可打印/不可打印字符
3. CAN FD 64 字节数据完整显示

## 6. Trace 自定义列配置需求（B16/B17）

### B16 - Trace 自定义列配置器

**优先级**: P1（高频使用场景，提升数据聚焦能力）  
**对标参考**: Wireshark Column Editor / CANalyzer Custom Data Columns  

**需求描述**:
允许用户添加自定义列到 Trace 表格，列的数据源可来自帧内任意字段，列头名称可自定义。

**功能点分解**:

| # | 功能 | 说明 |
|---|------|------|
| B16-1 | 自定义列编辑器对话框 | 添加/编辑/删除列；配置列名、表达式/字段源、显示格式、宽度、对齐方式 |
| B16-2 | 数据源字段选择 | 支持所有 CanFrame 成员：timestamp / channel / id / dlc / data[0]~data[7] / flags(fd/brs/esi/extended/rx/tx) |
| B16-3 | DBC 信号值引用 | 通过 DBC 报文名 + 信号名解析物理值（如 `Signal("ESP pressure")`），支持多信号组合（如 `Signal("Gear") & Signal("Speed > 50") ? "Moving" : "Stop"`） |
| B16-4 | 表达式引擎扩展 | 在现有 FilterEngine 基础上增加**格式化表达式**：`{field: expr}`；内置函数：timeSince(ref), hexData(start,len), signal(name) |
| B16-5 | 列实例化与持久化 | 每页 Trace 独立存储于 `.scolumn` JSON 文件；支持导入导出共享配置 |
| B16-6 | 排序/过滤联动 | 自定义列生成后可参与排序、过滤、标记（复用已有基础设施） |
| B16-7 | 表头右键列增删入口 | 表头右键菜单直接"添加列…"（打开编辑器）与"删除此列"（自定义列）；固定列仅允许隐藏，No. 列始终保留 |

**技术设计要点**:
- 新增 `CanTraceModel::CustomColumn` 类：包含列名、字段表达式、格式化规则、缓存策略
- 代理模型层扩展：在 `data()` 中检测自定义列索引，执行表达式求值并缓存结果
- 表达式求值复用 FilterEngine 的语法分析器，扩展 AST 节点类型支持字段访问和函数调用
- 性能优化：自定义列仅刷新变化行，采用可见行缓存机制，避免全量重算

**验收标准**:
1. 用户可以添加最多 8 个自定义列，每个列可配置：名称、数据源表达式、列宽、对齐
2. 支持以下数据源类型：数值型（整型/浮点）、时间戳、十六进制字符串、DBC 信号物理值
3. 示例场景：
   - 添加"Speed(km/h)"列：`signal("ESP speed") * 3.6`
   - 添加"FirstByteHex"列：`hex(data, 0, 1)` → "A1"
   - 添加"TimeSinceStart(s)"列：`timeSince(0)` → "12.34"
   - 添加"StatusText"列：`signal("Gear") == 1 ? "D" : (signal("Gear") == 2 ? "R" : "N")`
4. 保存配置后重新打开程序，自定义列自动恢复并正常工作
5. 对万帧规模数据集，自定义列的渲染不造成明显卡顿（延迟 ≤ 100ms）

**实现复杂度评估**: P1 级别（约 3-4 人日）
- UI 部分：自定义列编辑器对话框 + 表达式输入框 + 预览功能
- 后端部分：扩展表达式引擎、代理模型适配、缓存策略
- 测试部分：单元测试（表达式求值精度）、UI 回归测试（列拖拽/排序/过滤联动）

**关联影响**:
- 正向兼容：不影响已有固定列逻辑，自定义列从 ColCount 之后开始计数
- 依赖项：需复用 FilterEngine 的语法分析器和 CanFrame 数据模型
- 风险点：表达式求值性能（需基准测试百万帧场景）、DBC 信号动态查找开销

### B17 - Trace 列布局增强（列宽拖动体验 + 布局预设）

**优先级**: P2（体验增强，建立在已有的列宽拖动/顺序拖拽/显隐管理之上）  
**对标参考**: Wireshark "Resize Column To Fit" / Excel 列宽双击自适应  

**现状说明**:
列宽拖动（Interactive）、列顺序拖拽（SectionsMovable）、列显示/隐藏菜单、列布局 QSettings 持久化（宽度/顺序/可见性）**均已实现**（见 §2.1 第 11-13 项）。本需求为在此基础上的体验增强项。

**功能点分解**:

| # | 功能 | 说明 |
|---|------|------|
| B17-1 | 双击列边界自适应宽度 | 双击表头右边界，按当前可见行内容自动计算最优列宽（取样前 500 行） |
| B17-2 | 右键"自适应列宽"菜单 | 表头右键菜单增加：本列自适应 / 所有列自适应 |
| B17-3 | 布局预设管理 | 保存当前列布局（宽度+顺序+可见性+自定义列）为命名预设，多套预设一键切换；预设文件可导入导出共享 |
| B17-4 | 重置默认布局 | 表头右键菜单"重置布局"，一键恢复出厂列宽/顺序/可见性 |
| B17-5 | 列宽调整实时预览 | 拖动时显示实时像素值提示气泡（对齐 Wireshark 交互） |

**技术设计要点**:
- B17-1/2 复用 `QHeaderView::resizeSection()` + 源模型 `sizeHintForColumn()` 改造（需绕过视窗代理层取样源数据）
- B17-3 布局预设 = 现有 `saveColumnLayout()` 的 QSettings 结构平移为 JSON 文件（`settings/columns/*.scolpreset`）
- B17-5 需在 `FilterHeaderView` 的 mouseMoveEvent 中叠加一个无边框 QLabel 提示

**验收标准**:
1. 双击任意列右边界，该列宽度立即调整为可见内容最大宽度（含表头文字，上限 400px）
2. "所有列自适应"在一次操作内完成全部固定列 + 自定义列的宽度调整
3. 至少支持 5 套命名布局预设；切换预设后列宽/顺序/可见性/自定义列全部还原
4. 拖动列宽时鼠标旁显示如 "132 px" 的实时提示
5. "重置布局"恢复到 §2.1 表格中的出厂宽度（70/110/100/50/50/130/140/60/400/90/80）

**实现复杂度评估**: P2 级别（约 2-3 人日）
- B17-1/2/4 约 0.5 天；B17-3 约 1-1.5 天（含预设对话框 UI）；B17-5 约 0.5 天

**关联影响**:
- 依赖项：B16（自定义列参与预设时）；FilterHeaderView（B17-5 需扩展该类）
- 风险点：视窗代理层下的列宽取样性能（仅取样可见行 + 前 500 行规避全表扫描）
