## 四、质量保障（本批次执行的验证）

1. **语法校验**：32 款插件全部通过 `python -m py_compile` 编译检查（32/32 OK）。
2. **冒烟测试**（关键算法模块）：
   - 位时序求解器：40MHz/500kbps/87.5% → BRP=10, N=8, TSEG1=6, TSEG2=1, **误差 0.000%**；FD 数据段 2Mbps@70% 采样点同样 0.000% 误差；经典 8 字节帧时长估算 0.262ms（数量级正确）。
   - E2E CRC 引擎：通过业界标准测试向量校验 —— CRC16-CCITT("123456789")=0x29B1 ✓、CRC32-MPEG-2("123456789")=0x0376E6E7 ✓（修正了初版 CRC32 异或输出参数：E2E P04 采用 MPEG-2 变体 xorout=0）、XOR-8 ✓。
3. **安全基线**：所有发送类插件（can-frame-generator / can-fuzzer / can-stress / can-simulator / can-gateway）激活时**零发送**，仅在用户点击按钮后注入流量，且带红色警示；所有订阅类插件严格只读。
4. **自包含打包**：.opk 仅打包插件目录，dbcparse.py（423 行纯 Python DBC 解析器）已复制进 11 个需要 DBC 能力的插件目录，isotp_client.py 复制进 2 个 UDS 插件目录，离线可用。

## 六、本批次新开发插件的工程要点

- 统一遵循插件模板：`activate(context)` / `deactivate()` 生命周期、`context.on_frame()` 订阅、`context.register_command()` 菜单注册、`sin.ui.create_window()` 独立窗口。
- 高频 UI 全部基于 QTreeWidget/QTimer 刷新模式，帧回调内只做数据记录，避免跨线程 Qt 调用。
- can-dashboard 采用 QWidget 子类重写 `paintEvent` 实现 QPainter 自绘仪表（圆形仪表/柱状/数字三种部件，阈值越限变红）。
- can-ids 实现学习模式（μ±3σ 基线）+ 监控模式（新 ID / 速率异常 / 恒定载荷突变三类告警，同类告警 10 秒节流）。
- e2e-checksum 支持多规则实时校验：CRC8-J1850 / CRC8H2F / CRC16-CCITT / CRC32-MPEG-2 / XOR-8，CRC 位置与保护范围可配，alive counter 4bit 递增检查（重复/跳变分类告警）。
- can-bit-timing 为纯离线工具：双相位（仲裁+数据）BRP/TSEG 搜索（≤2% 误差，按波特率与采样点误差排序）、TDC 环回延迟估算、帧时长与利用率估算。
