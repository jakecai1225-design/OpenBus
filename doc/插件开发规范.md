# OpenBus 插件开发规范

> **地位：** 领域套件（`*-suite` / `*-studio`）后续开发的**总准则**。  
> **来源：** 从 CANopen Suite 等多轮 PDCA 中剥离的方法论、设计原则、UI/UX 与流程约定（不含具体业务协议细节）。  
> **配套：** [Suite_UI_UX_Design_System.md](Suite_UI_UX_Design_System.md)（视觉细则）· [Plugin_Domain_Suites.md](Plugin_Domain_Suites.md)（套件地图）· `.cursor/rules/ui-ux-philosophy.mdc` · `pdca-two-rounds.mdc` · `plugin-live-source.mdc` · `no-chinese-in-code.mdc`  
> **对标体验：** VS Code Light 工业 IDE 密度；**壳层强制四件套**（Activity · Side Bar · Editor Tabs · OUTPUT），见 §3。  
> **参考实现：** `canopen-suite` / `dbc-studio` / `eds-studio` / `uds-suite` / `obd-suite` / `j1939-suite` / `autosar-suite` / `ethercat-suite`。

---

## 1. 产品定位

| 要 | 不要 |
|----|------|
| 一个领域 = 一个插件 = **一条龙应用** | 拆成十几个「单页工具」 |
| 共享会话（连接 / 选中 / 草稿 / 日志） | 每页各自一份连接条 / 日志副本 |
| 打开即可走完常用闭环 | 打开只看到设置或说明书 |
| 对标该领域独立软件的主路径 | 「功能齐全」但路径割裂 |

**一句话：** 插件是**应用**，不是对话框集合。

**产品面：** 只上架领域套件（`*-suite` / `*-studio`）与 AI Agent。多工具合集（TX Lab、Bus Security、Protocol Hub、Log Analysis、Bus Utilities）已退役至 `plugins/_retired/`，不得再作为独立产品入口出现在插件面板或市场。

## 2. 设计原则（必须遵守）

### 2.1 主工作面优先

- 主区域永远是**当前任务**（树 / 表 / 编辑器 / 波形），不是设置、说明或状态墙。
- 次要 chrome（侧栏、OUTPUT、状态、菜单）**安静、可收缩**，不得与内容抢注意力或高度。
- **一个水平 chrome 行**：不要叠标题栏 + 芯片条 + 第二套 Tab。

### 2.2 一条金路径（Foolproof primary path）

- 为该领域写清 **1～3 条黄金旅程**（如：打开 → 编辑 → 校验 → 应用 → 在线 → 导出）。
- 每条旅程：**空态 / 成功 / 阻塞** 都必须有 **1～2 个动词 CTA**（打开某页 / 执行某动作），禁止「只有一段灰字」。
- **Context Next（建议下一步）**：状态栏或文档区保留一个随会话推进的「下一步」按钮；不得在某一环永久卡住。

### 2.3 连续性（页连续 · 操作连续 · 过程连续）

- 选中对象、节点、文件路径在页间 **携带**（`set_focus` / 等价会话字段），不要让用户重选。
- 动作完成后给出**可见过桥**（next_step_bar、菜单、或 Context Next），而不是只写日志。
- 文件类能力进 **File 菜单**；编辑叶子进侧栏——**侧栏不做文件浏览器**。

### 2.4 信息架构克制

- Activity（活动栏）只放 **大工作区**（通常 ≤ 4～5 个）。日志不是活动页。
- 侧栏叶子：**一叶一事**；发现定位重复则合并或降级到 View / Device 菜单。
- 同域「文件层」与「总线层」能力若易混淆，用文案与入口隔离（例：文件映射 vs 在线映射），侧栏只保留主路径。

### 2.5 少而准，而非全而吵

- 能力可以深，但**默认露出**只保留主路径；高级入口进菜单 / 折叠 / 隐藏状态即可。
- 禁止为「完整性」增加第二工具条、说明行、嵌套卡片。

## 3. 壳层与导航（Workbench）— VS Code 四件套（强制）

> **产品对标：** VS Code Light 工作台。领域套件**必须**具备下列四件套，禁止「有的套件有、有的没有」。  
> **共享实现：** `plugins/_shared/suite_chrome.py` · `suite_tabs.py` · `suite_ui.py` · `vscode_theme.py` · `codicons`

### 3.1 标准骨架

```
Menu bar（File · Edit · View · Help · 右侧布局开关）
Activity bar（左窄条 · 大工作区 ≤5）
  └─ Side Bar（该工作区叶子 · Ctrl+B · 默认可见）
  └─ Editor chrome 行（可关闭 Tab 驻留 · 仅标题/Tab，无布局图标）
       └─ 当前页内容（tool_strip → 工作面）
  └─ OUTPUT 底栏（一排工具 + 列表 · Ctrl+J · 默认可见）
  └─ 状态栏（路径 / 脏标 / 会话摘要 / Context Next）
```

对比 VS Code：

| VS Code | OpenBus 套件 | 强制？ |
|---------|--------------|--------|
| Activity Bar | `NAV_PAGES` + Activity 图标条 | **必有** |
| Side Bar | `side_bar_enabled=True` + `workspace_sidebar` 叶子 | **必有** |
| Editor Tabs | `_open_tabs` + `suite_tabs.mount_editor_tabs` | **必有** |
| Panel（OUTPUT） | `panel_title="OUTPUT"` + `panel_tools` / `panel_body` | **必有** |
| Status Bar | `plugin_shell.attach_status_bar` + Context Next | **必有** |
| Menu Bar | File · Edit · View · Help（+ 领域菜单） | **必有** |
| 布局开关 | 菜单栏右侧 `attach_layout_toggles_to_menubar` | **必有** |

### 3.2 四件套规则（一条一条）

| 元素 | 规则 |
|------|------|
| **Activity** | 只放大工作区，**≤ 4～5**；日志不是 Activity；图标用 `codicons` |
| **Side Bar** | `build_workbench(..., side_bar_enabled=True, side_bar_visible=True, lock_activity=True)`；每 Activity 一份侧栏；**一叶一事**；叶子点击 → **开 Tab**（不是只换栈） |
| **Editor Tabs** | 侧栏叶子 / `goto_page` / `run_action(...goto...)` 一律 `_open_feature_tab`；可关闭；关光最后一个必须 reopen 该工作区**默认叶子**；实现 `_on_workbench_page`，禁止 `set_editor_title` 清掉 Tab（见 §13.1） |
| **OUTPUT** | 壳层唯一底栏；Pause / Export / Clear 一排工具；**禁止** Log 活动页、禁止每页再挂一份日志 |
| **快捷键** | Ctrl+B 侧栏 · Ctrl+J OUTPUT · Ctrl+Shift+E Maximize · Ctrl+1…N 切 Activity；默认侧栏与 OUTPUT **可见** |
| **连接 / 总线** | 仅 Setup（或薄状态栏）；**禁止**每页全宽连接条 |
| **菜单** | File（文档/工程/DBC/配置）· Edit · View（含 Toggle Side Bar / OUTPUT / Maximize）· Help；领域菜单按需 |
| **布局开关图标** | 仅挂在菜单栏右上角；与 min/max/close **同行同高**（§13.9）；**禁止**再挂到 Editor chrome 行 |
| **窗口标题栏** | 套件 `QMainWindow` **无 OS 标题栏**（frameless）；品牌 + 菜单 + 窗口按钮一行（§13.9） |

### 3.3 实现清单（新套件 / 改造套件开工即勾）

```text
[ ] suite_chrome.build_workbench(..., side_bar_enabled=True, panel_visible=True)
[ ] workspace_sidebar.py：每 Activity 的叶子列表 + select_section（深目录对照 §3.4）
[ ] FEATURE_ROUTE / FEATURE_TITLES / _WORKSPACE_DEFAULT / _PAGE_ALIASES
[ ] _open_tabs + suite_tabs.mount_editor_tabs + _open_feature_tab / _close_feature_tab
[ ] _on_workbench_page / _on_activity_clicked（侧栏开 Tab，不清条）
[ ] OUTPUT：panel_tools + make_output_table（或等价）
[ ] pages/_ui.py → from _shared.suite_ui import *（密度与控件同源）
[ ] vscode_theme.apply / apply_*_chrome；英文 UI；tests/test_shell_routes.py
```

参考实现（壳层已对齐）：`canopen-suite`、`dbc-studio`、`eds-studio`、`uds-suite`、`obd-suite`、`j1939-suite`、`autosar-suite`、`ethercat-suite`。

### 3.4 Side Bar 树形组织（对标 VS Code Explorer）

侧栏是 **Explorer**，不是又一条活动栏。组织方式对齐 VS Code：

```text
VIEW TITLE          # SuiteSideBarHeader，全大写 muted（如 CONFIG）
[可选 Filter]       # 仅目录类 catalog 需要；高度 = FILTER_H
▼ Folder            # 容器：folder 图标 + twistie；expand/collapse；默认不整树展开
    ▶ Group         # 子文件夹：同样 folder；默认折叠
        Leaf        # 叶子：file / 领域图标；可选中 → 开 Tab
Leaf                # 无子节点的功能叶：图标 + DontShowIndicator
▼ Tools folder      # 相关工具收进文件夹，勿与 catalog 平铺抢视线
    Findings …
```

| 角色 | 规则 |
|------|------|
| **容器（folder / group）** | `codicons` `folder`；可加粗；**不可选中**（或只负责展开）；点击 = 展开/折叠 |
| **叶子（section / module / file）** | 固定领域图标（`edit` / `file` / `check`…）；可选中；点击 → `goto_page` / 开 Tab |
| **默认展开** | 只展开**当前路径**（活动叶子所在文件夹 + catalog 根）；**禁止**启动时把所有 group 全部展开 |
| **过滤** | 过滤时展开命中组；清空过滤后恢复「组折叠」 |
| **图标** | 每行必有 Codicon（16px）；禁止纯文字树 |
| **缩进** | `style_tree` / indentation ≈ 12；字号 12px（§13.14） |

浅侧栏（UDS Diagnose 等无嵌套）：`setRootIsDecorated(False)` + 扁平叶子 + 图标即可。  
深目录（AUTOSAR Config BSW、DBC Network 树）：必须用上表容器/叶子分层。参考：`autosar-suite/pages/config_sidebar.py`。

## 4. 页面 Chrome 配方（强制）

每一工作页统一为：

1. **`tool_strip` 或 `panel_header`** — 一行，高度 = `TOOL_H`（38）；仅当真正需要过滤/模式控件时使用  
2. 可选 **`inline_filter`** — 高度 = `FILTER_H`（= `TOOL_H`）  
3. **工作面**（树 / 表 / 表单 / 分栏）— `stretch`；页级动作优先 **`content_header` + `icon_tool` / `ghost_btn`**  
4. 可选 **`next_step_bar` / `empty_state`** — 仅在需要时出现  

**禁止：**

- 标题下再挂一排说明 Caption  
- 双层工具条  
- **Editor Tabs 正下方再挂一排满宽文字按钮 tool_strip**（与 Tab 抢戏、显得突兀）— 空态用 `empty_state`；有内容时用 `content_header` + `icon_tool`，或 File/菜单承载；**禁止**在 Tab 下用 `primary_btn` 做第二标题栏  
- 嵌套卡片、厚分隔、抢戏的状态大字  

**提示放 Tooltip**，不放占垂直空间的 Hint 行。

### 4.1 密度 Token（强制同源：`plugins/_shared/suite_ui.py`）

各套件 `pages/_ui.py` **优先** `from _shared.suite_ui import *`（或显式 re-export），禁止自研第三套魔法高度。

| Token | 建议值 | 用途 |
|-------|--------|------|
| `CTRL_H` | 28 | 按钮 / 输入 / 下拉的**外框高度**（`setFixedHeight(CTRL_H)`） |
| `CTRL_INNER` | **26**（`CTRL_H - 2`） | QSS **内容盒** `min/max-height`（配合 `border: 1px`、垂直 `padding: 0`） |
| `STRIP_PAD_V` | 4 | 工具条 / 过滤条上下内边距 |
| `STRIP_EDGE` | 2 | strip 底边框 + DPI 余量（共享 `suite_ui`） |
| `TOOL_H` | `CTRL_H + 2×STRIP_PAD_V + STRIP_EDGE`（**38**） | 工具条 / 面板头（须完整露出控件四边框） |
| `FILTER_H` | **= `TOOL_H`** | 过滤条（与工具条同高，禁止更矮） |
| `ICON` / `ICON_TOOL` | **≥14**（chrome **16**） | 按钮 / 图标钮；禁止 10px 模糊 |
| `ROW_H` | 26 | 列表行（防 Win DPI 裁切） |
| `PAD_X` / `GAP` | 10 / 6 | 边距与间距 |
| `PANE_MIN` / `PANE_MIN_PROP` | 180 / 200 | 分栏下限，保证可拖 |

**硬约束：**

1. `TOOL_H` / `FILTER_H` = `CTRL_H + 2×STRIP_PAD_V + STRIP_EDGE`（38）。更矮 → 输入框**缺底边**（§13.6）。
2. Qt Style Sheets 的 `min-height` 是**内容盒**：`min-height: 28` + `padding: 2px` + `border: 1px` ≈ **34px 外框**，再被 strip 裁切。输入控件 QSS 必须用 `CTRL_INNER` + 垂直 `padding: 0`，外框只靠 `setFixedHeight(CTRL_H)`。
3. `SuiteStripField` / `StepSpin` / strip 内 `QLineEdit`·`QComboBox` 一律钉 `CTRL_H`；禁止 strip 容器 `max-height: 32`。
4. 工作面正文字号统一 **12px**（Tab / 树 / 标题 / 表单标签同一档；§13.14）。
5. 页面内**禁止魔法高度**；一律引用 Token。

### 4.2 分栏

- 使用共享 `configure_splitter`：**不透明实时改宽**（两侧一起变宽，禁止「一页盖住另一页」）。  
- 主工作面 : 属性/目录 ≈ 黄金分割；主面在左或右按任务定，但须一致。  
- `ScrollBarAsNeeded` + 长文 `ElideRight`；目录类列表横向滚动条默认关闭。

| 项 | 规范 |
|----|------|

## 6. 会话、命令与互操作

### 6.1 SharedSession（或等价）

套件内单一会话对象，至少承载：

- 当前文档 / 工程路径与脏标记  
- 共享业务选择（节点、焦点索引等）  
- 草稿 vs 已应用数据（若存在两层）  
- 日志回调、帧/事件订阅  

跨页读会话，**不要**用页面局部全局变量硬传。

### 6.2 `run_action` 命令总线

菜单、空态、Context Next、页内按钮统一走：

```text
run_action("domain.verb", **kwargs)
```

新增能力先登记 handler，再挂 UI。禁止页内直接「只改自己、不通知壳」。

### 6.3 焦点携带

- 树/表选中 → `document.set_focus` / `session.set_focus`（或等价）  
- 焦点变化应 **`on_focus` 通知**（不必等同 `on_changed` / dirty）  
- 目标页打开或激活时消费焦点并高亮/填充；提供 `goto_*_target` 类跳转  
- Context Next / next_step / 右键菜单应能带着上下文跳转（见 §13.2）  

### 6.4 Context Next 启发式

确定性阶段机即可，例如：无文档 → 保存 → 校验 → 应用 → 在线观察 → 导出。  
每执行一次建议动作应能**推进阶段**，避免死循环在同一步。

## 7. 文件、工程与侧栏分工

| 能力 | 归属 |
|------|------|
| New / Open / Save / Recent / 工程内文件列表 | **File 菜单** |
| 编辑叶子（对象、映射、校验、配置视图…） | **侧栏** |
| 电源级在线视图（若侧栏已饱和） | Device / View 菜单 |
| 首屏引导 | 空态 CTA + Context Next；**不要**第五个「开始」Activity |

工程多文档：列表与「主文件」标记放 File 子菜单或工程对话框；侧栏保持编辑导航干净。

## 9. 质量门禁：PDCA × 2

**任何产品需求不得「改一版即结案」。** 必须两轮完整 PDCA：

1. **P** Plan：缺口、目标、验收、风险、Out of scope  
2. **D** Do：只实现 Plan 所列  
3. **C** Check（分文件）：Test · UX（对照本规范 + 金路径）· Accept  
4. **A** Act：保留 / 修复 / 丢弃 → 喂给 Round 2；Round 2 Accept 通过才 **CLOSED**

临时文档目录：`tmp/pdca/<suite>-<feature>/`（`STATUS.md`、`R{n}-P|D|C-*|A-*.md`）。

质量条：顶级密度、chrome 纪律、主路径傻瓜化；逻辑单测 + 关键 UI 契约测试；禁止静默回退。

## 11. 新套件开工清单

1. 写清领域金路径（≤3）与对标边界（做 / 不做）。  
2. **先落地 §3 VS Code 四件套**（勾完 §3.3 清单再写业务页）。  
3. Activity ≤ 5；侧栏叶子无重复；File 管文件；Log ≠ Activity。  
4. `suite_chrome` + `suite_tabs` + `pages/_ui` → `suite_ui` + `vscode_theme` + codicons。  
5. SharedSession + `run_action` + Context Next；持久化 `open_tabs`。  
6. 每页：`tool_strip` / 空态 CTA；无连接条副本、无 OUTPUT 副本。  
7. 英文 UI；源码 `plugins/<id>/` 热加载验证。  
8. 首个需求起走 PDCA×2；`tmp/pdca/` 留痕；R1 Accept 含四件套全绿。

## 12. 反模式速查（看见即改）

- **缺 Side Bar**（`side_bar_enabled` 未开，或 Activity 直接换整页无叶子导航）  
- Side Bar 纯文字树、无 Codicon；或启动时**整棵 catalog 全展开**（应对齐 §3.4）

### 13.1 编辑器 Tab 驻留（侧栏 → 主窗）

| 踩坑 | 强制对策 |
|------|----------|
| 侧栏只换 `QStackedWidget` + `set_editor_title`，叶子无法多开、无法关闭 | 有子功能的工作区必须走同款：`_open_tabs` + `_mount_tab_bar` + `_open_feature_tab` / `_close_feature_tab`；`goto_page` / 侧栏 `on_select` 一律开 Tab |
| 点侧栏叶子后 **Tab 条消失**，点 Activity 才回来 | 根因：`suite_chrome.highlight_activity` → `_select_page` 在无 `_on_workbench_page` 时调用 `set_editor_title`，**清掉**已挂的 Tab。对策：① 套件实现 `_on_workbench_page`；② chrome 在已有 `_chrome_tabs` 时禁止标题覆盖；③ Activity 键列入 `tab_pages` 或等价白名单 |

| 页内再挂 `chrome_tabs` 抢 chrome 行 | Dictionary\|Device、Starters\|Profiles 等**分段**留在页内（`SuiteSegmentTabs`），不要 `root.chrome_tabs` 挂进主窗 |

### 13.2 同域页间互操作（打通）

| 踩坑 | 强制对策 |

| Messages / Value tables / Attributes（或 OD / Dictionary / PDO）各管各的选中 | Document / Session 提供 `set_focus` + **`on_focus` 通知**（焦点变了不必 `mark_dirty`）；目标页 `refresh` / `select_*` 消费焦点 |

### 13.9 菜单栏一行（VS Code 无标题栏）

套件窗口**禁止**再叠一层 OS 标题栏。`attach_layout_toggles_to_menubar` 负责：

```text
File Edit View Run Help                  [dirty] [sidebar|panel|max] | [─ □ ×]
←—————— 纯文字菜单（VS Code）————————————————————————————————————————→
```

顶级菜单保持 **文字**（`SuiteMenuButton` TextOnly，无下拉箭头、无图标条）；**禁止**在 File 左侧再放品牌/扩展小图标；领域项（Import / Project / BSW）收进 File 子菜单；Validate → Run。密度对齐宿主：`CHROME_BTN_H=30`、布局 36、窗口钮 46、图标 16。

| 踩坑 | 强制对策 |
|------|----------|
| OS 标题栏 + QMenuBar 两行（浪费垂直空间，按钮大小不一致） | helper 设 `FramelessWindowHint`；min/max/close 挂在菜单行右侧 |
| 用 `setCornerWidget` / 嵌套 `QMenuBar` 导致 File/Edit 不绘制或挤进 `»` | 中央 `SuiteMenuChromeSlot` + **`SuiteMenuButton` InstantPopup**（harvest 菜单）；**禁止**把 File/Edit 挂在 `setMenuWidget` |
| Tab 挂载后调用 `menuBar()` / `setCornerWidget`，File/Edit 整行消失 | Qt：`menuBar()` 会删掉 `setMenuWidget` 控件。`_mount_tab_bar` **禁止**再碰 menubar；官方区用高度 0 的 `SuiteMenuBarSentinel` |
| 布局钮与 min/max/close 大小不一、挤成一团 | 统一 `CHROME_ICON=16`、按钮高 30；工具 / 布局 / 窗口三组之间加竖线分隔 |
| Editor chrome 行再挂 Side Bar / Panel / Maximize | `build_workbench` 不把布局钮加进 chrome；只用 `attach_layout_toggles_to_menubar` |
| 布局钮 28×28 / 12px 图标，窗口钮另一套尺寸 | 统一 Token：`CHROME_BTN_H=30`、布局宽 36、窗口钮宽 46、图标 **16px**（与宿主 `mainwindow_chrome` / `suite_chrome` 一致） |

| 无边框后无法拖动 / 双击最大化 | helper 在菜单空白区 `startSystemMove`；双击切换 maximize |

### 13.13 菜单栏 File / Edit 点不动（幽灵子控件）

典型现象：菜单文字可见甚至未灰显，但鼠标点 File / Edit 无反应；`childAt(菜单区)` 命中某个 **100×30 无名 `QWidget`**，而不是 `QMenuBar`。

| 踩坑 | 强制对策 |
|------|----------|
| `page(parent)` / `QWidget(AppShell)` 建了 holder，只把 `leaf_pages` 挂进 stack，**holder 自己留在 `QMainWindow` 子树** | holder 用 `page(None)`（或无 parent），立刻 `hide()` + `WA_DontShowOnScreen`；需要时 `self._xxx_host = holder` 保活给对话框 |
| harvest 的 `QMenu` `setParent(标签)` 后仍 **visible**，整块菜单面板盖住 File/Edit（点一下才消失） | `_park_popup_menu`：`Popup` 窗口标志 + `hide()`；父对象用 window，**禁止**把 QMenu 嵌成标签的可见子控件 |
| `setParent(None)` 的可见控件短暂变成顶层窗，盖住左上角 | 停靠用隐藏 park（`hide` + `WA_DontShowOnScreen`）；可见子控件必须进 layout / stack / menubar corner |
| 调试时只看菜单是否 `enabled` | 用 `window.childAt(menuBar.mapTo(window, QPoint(40,15)))`；若不是 `QMenuBar`，即有覆盖物 |

验收：File / Edit / View 可点开；`AppShell` 上除 `centralWidget` / `menuBar` / `statusBar` 外无可见的直接子 `QWidget`。

参考：`uds-suite/pages/diagnose.py`（Diagnose holder）；凡「只抽叶子、丢弃 root」的 `build()` 一律自查。

### 13.14 工作面字号不齐（Tab / 树 / 标题 / 表单）

| 踩坑 | 强制对策 |
|------|----------|
| 各套件自定 13px Tab / 树，或 `FS_BODY=13`（DBC）与共享 12px 混用 | 统一类型刻度（`vscode_theme`）：**`FS_BODY=FS_CTRL=FS_MENU=12`**，**`FS_META=11`**；`suite_ui` / 各套件 `_ui` 只 re-export，禁止本地另起字号 |
| 树未 `style_tree` → 继承旧 13px | 目录 / 服务树一律 `_ui.style_tree`（`SuiteMatrix`） |
| `QFormLayout.addRow("Control:", w)` 标签无 objectName → 与 12px 控件「一大一小」 | 主题已强制 `QLabel { font-size: 12px }`；表单行仍须 `field_label(...)` / `value_label(...)`，建完行后 `polish_form_labels(form)`；**禁止**裸 `addRow("文字", w)` 与内联 `font-size:16px/16pt` |
| chrome 元信息与正文抢戏 | Side Bar 标题等 meta 仍可用 **11px** muted；正文区不要再用 13px「标题墙」 |
| Side Bar 顶栏大字/裁切 | 对标 VS Code `.part > .title`：**行高 35px** + `QLabel#SuiteSideBarTitle`（**11px** muted uppercase）；禁止 `max-height:22`（那是 pane-header）或 `SuiteToolbarTitle` 冒充 viewlet 标题；`apply_*_chrome` 必须在 `build_workbench` **之后**（否则 overlay 被 `vscode_theme.apply` 冲掉） |

实现落点：`vscode_theme` + `_shared/suite_ui` 叠层；套件页禁止局部另起字号（分类加粗可保留，但 **pixelSize=12**）。
