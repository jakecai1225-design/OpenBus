# OpenBus 插件开发规范

> **地位：** 领域套件（`*-suite` / `*-studio`）后续开发的**总准则**。  
> **来源：** 从 CANopen Suite 等多轮 PDCA 中剥离的方法论、设计原则、UI/UX 与流程约定（不含具体业务协议细节）。  
> **配套：** [Suite_UI_UX_Design_System.md](Suite_UI_UX_Design_System.md)（视觉细则）· [Plugin_Domain_Suites.md](Plugin_Domain_Suites.md)（套件地图）· `.cursor/rules/ui-ux-philosophy.mdc` · `pdca-two-rounds.mdc` · `plugin-live-source.mdc` · `no-chinese-in-code.mdc`  
> **对标体验：** VS Code Light 工业 IDE 密度；UDS Suite 为壳层参考实现，成熟套件的产品闭环可参考近期 PDCA 实践。

---

## 1. 产品定位

| 要 | 不要 |
|----|------|
| 一个领域 = 一个插件 = **一条龙应用** | 拆成十几个「单页工具」 |
| 共享会话（连接 / 选中 / 草稿 / 日志） | 每页各自一份连接条 / 日志副本 |
| 打开即可走完常用闭环 | 打开只看到设置或说明书 |
| 对标该领域独立软件的主路径 | 「功能齐全」但路径割裂 |

**一句话：** 插件是**应用**，不是对话框集合。

## 2. 设计原则（必须遵守）

### 2.1 主工作面优先

- 主区域永远是**当前任务**（树 / 表 / 编辑器 / 波形），不是设置、说明或状态墙。
- 次要 chrome（侧栏、OUTPUT、状态、菜单）**安静、可收缩**，不得与内容抢注意力或高度。
- **一个水平 chrome 行**：不要叠标题栏 + 芯片条 + 第二套 Tab。

### 2.2 一条金路径（Foolproof primary path）

- 为该领域写清 **1～3 条黄金旅程**（如：打开 → 编辑 → 校验 → 应用 → 在线 → 导出）。
- 每条旅程：**空态 / 成功 / 阻塞** 都必须有 **1～2 个动词 CTA**（打开某页 / 执行某动作），禁止「只有一段灰字」。
- **Context Next（建议下一步）**：状态栏或文档区保留一个随会话推进的「下一步」按钮；不得在某一环永久卡住。

### 2.3 连续性（页连续 · 操作连续 · 过程连续）

- 选中对象、节点、文件路径在页间 **携带**（`set_focus` / 等价会话字段），不要让用户重选。
- 动作完成后给出**可见过桥**（next_step_bar、菜单、或 Context Next），而不是只写日志。
- 文件类能力进 **File 菜单**；编辑叶子进侧栏——**侧栏不做文件浏览器**。

### 2.4 信息架构克制

- Activity（活动栏）只放 **大工作区**（通常 ≤ 4～5 个）。日志不是活动页。
- 侧栏叶子：**一叶一事**；发现定位重复则合并或降级到 View / Device 菜单。
- 同域「文件层」与「总线层」能力若易混淆，用文案与入口隔离（例：文件映射 vs 在线映射），侧栏只保留主路径。

### 2.5 少而准，而非全而吵

- 能力可以深，但**默认露出**只保留主路径；高级入口进菜单 / 折叠 / 隐藏状态即可。
- 禁止为「完整性」增加第二工具条、说明行、嵌套卡片。

## 3. 壳层与导航（Workbench）

标准骨架（共享 `plugins/_shared/suite_chrome.py`）：

```
Activity bar（大工作区）
  └─ Side bar（该工作区叶子）
  └─ Editor（一排 chrome：Tab 或标题 + 布局开关）
       └─ 当前页内容
  └─ OUTPUT（一排工具 + 列表；Ctrl+J）
  └─ 状态栏（路径 / 脏标 / Node·会话摘要 / Context Next）
```

| 规则 | 说明 |
|------|------|
| Ctrl+B / Ctrl+J | 侧栏 / OUTPUT 显隐；默认侧栏可见 |
| 连接 / 总线 / 会话参数 | 独立页或薄状态控件，**禁止**每页复制一条全宽连接条 |
| 编辑器 Tab | 仅当工作区有子功能需要并排打开时；侧栏叶子与 Tab 语义对齐，别名折叠为同一 Tab |
| 菜单 | File（文档/工程）· Edit · 领域菜单 · View · Help；电源级入口可放 Device/View，不抢侧栏 |

## 4. 页面 Chrome 配方（强制）

每一工作页统一为：

1. **`tool_strip` 或 `panel_header`** — 一行，高度 ≈ 32px  
2. 可选 **`inline_filter`** — 过滤控件高度 = 字段高度  
3. **工作面**（树 / 表 / 表单 / 分栏）— `stretch`  
4. 可选 **`next_step_bar` / `empty_state`** — 仅在需要时出现  

**禁止：**

- 标题下再挂一排说明 Caption  
- 双层工具条  
- 嵌套卡片、厚分隔、抢戏的状态大字  

**提示放 Tooltip**，不放占垂直空间的 Hint 行。

### 4.1 密度 Token（建议各套件 `_ui.py` 对齐）

| Token | 建议值 | 用途 |
|-------|--------|------|
| `CTRL_H` | 28 | 按钮 / 输入 / 下拉 |
| `TOOL_H` | 32 | 工具条 / 面板头 |
| `FILTER_H` | 34 | 过滤条（略高于字段） |
| `ICON` / `ICON_TOOL` | 16 | 按钮 / 图标钮 |
| `ROW_H` | 26 | 列表行（防 Win DPI 裁切） |
| `PAD_X` / `GAP` | 10 / 6 | 边距与间距 |
| `PANE_MIN` / `PANE_MIN_PROP` | 180 / 200 | 分栏下限，保证可拖 |

页面内**禁止魔法高度**；一律引用 Token。

### 4.2 分栏

- 使用共享 `configure_splitter`：**不透明实时改宽**（两侧一起变宽，禁止「一页盖住另一页」）。  
- 主工作面 : 属性/目录 ≈ 黄金分割；主面在左或右按任务定，但须一致。  
- `ScrollBarAsNeeded` + 长文 `ElideRight`；目录类列表横向滚动条默认关闭。

## 5. 控件与视觉

| 项 | 规范 |
|----|------|
| 主题 | `vscode_theme.apply` + 套件 overlay；VS Code Light 系 |
| 图标 | `_shared/codicons` + SVG；主/次按钮配真实图标；禁止 emoji / 字符当图标 |
| 主按钮 / Ghost / Icon tool | Primary 填色强调；Ghost 次要；Icon-only 28×28 命中区 |
| 表单 | 标签右对齐、同一基线；输入四边框完整可见 |
| 复选 | 选中必须可见勾选 |
| 空态 | `empty_state(title, hint, actions=[…])`，动作进 `run_action` / `goto_page` |
| 下一步条 | `next_step_bar("…", btn1, btn2)`，用完隐藏 |
| 边框 | **一块连续表面**；允许导航右边线、Tab 下划线、控件边框；禁止卡片汤 |

更细的视觉表见 [Suite_UI_UX_Design_System.md](Suite_UI_UX_Design_System.md)。

## 6. 会话、命令与互操作

### 6.1 SharedSession（或等价）

套件内单一会话对象，至少承载：

- 当前文档 / 工程路径与脏标记  
- 共享业务选择（节点、焦点索引等）  
- 草稿 vs 已应用数据（若存在两层）  
- 日志回调、帧/事件订阅  

跨页读会话，**不要**用页面局部全局变量硬传。

### 6.2 `run_action` 命令总线

菜单、空态、Context Next、页内按钮统一走：

```text
run_action("domain.verb", **kwargs)
```

新增能力先登记 handler，再挂 UI。禁止页内直接「只改自己、不通知壳」。

### 6.3 焦点携带

- 树/表选中 → `session.set_focus(...)`  
- 目标页打开时消费焦点并高亮/填充  
- Context Next / next_step 应能带着上下文跳转  

### 6.4 Context Next 启发式

确定性阶段机即可，例如：无文档 → 保存 → 校验 → 应用 → 在线观察 → 导出。  
每执行一次建议动作应能**推进阶段**，避免死循环在同一步。

## 7. 文件、工程与侧栏分工

| 能力 | 归属 |
|------|------|
| New / Open / Save / Recent / 工程内文件列表 | **File 菜单** |
| 编辑叶子（对象、映射、校验、配置视图…） | **侧栏** |
| 电源级在线视图（若侧栏已饱和） | Device / View 菜单 |
| 首屏引导 | 空态 CTA + Context Next；**不要**第五个「开始」Activity |

工程多文档：列表与「主文件」标记放 File 子菜单或工程对话框；侧栏保持编辑导航干净。

## 8. 工程与编码约定

| 项 | 要求 |
|----|------|
| 语言 | **非 Markdown 禁止中文**（代码、JSON、脚本、UI 字符串、日志）— 见 `no-chinese-in-code` |
| 源码路径 | 编辑 `plugins/<id>/`；运行时优先加载源码树（`plugin-live-source`） |
| 验证 Python UI | 改源码 → 重启或重激活套件；**不要**为看效果去打 `.opk` |
| `.opk` | 仅发市场包时打包 |
| 共享库 | 优先 `plugins/_shared/`（theme、codicons、suite_chrome、widgets） |
| 状态 | `state_store` 持久化布局、最近文件、活动页；深度链接用别名表折叠到现行叶子 |

## 9. 质量门禁：PDCA × 2

**任何产品需求不得「改一版即结案」。** 必须两轮完整 PDCA：

1. **P** Plan：缺口、目标、验收、风险、Out of scope  
2. **D** Do：只实现 Plan 所列  
3. **C** Check（分文件）：Test · UX（对照本规范 + 金路径）· Accept  
4. **A** Act：保留 / 修复 / 丢弃 → 喂给 Round 2；Round 2 Accept 通过才 **CLOSED**

临时文档目录：`tmp/pdca/<suite>-<feature>/`（`STATUS.md`、`R{n}-P|D|C-*|A-*.md`）。

质量条：顶级密度、chrome 纪律、主路径傻瓜化；逻辑单测 + 关键 UI 契约测试；禁止静默回退。

---

## 10. 测试最低要求

| 类型 | 内容 |
|------|------|
| 路由 / IA | Activity 键、侧栏叶子、别名折叠、禁止幽灵页进栈 |
| 会话 | focus、next_hint 阶段、脏标记 |
| 契约 | 禁止已删 chrome 文案复现（如「第二工具条」「Fine-tune」类） |
| 无中文 | 抽样扫描壳与关键页源码无 CJK |
| 手册 | 每需求附带金路径点击清单（人工） |

## 11. 新套件开工清单

1. 写清领域金路径（≤3）与对标边界（做 / 不做）。  
2. Activity ≤ 5；侧栏叶子无重复；File 管文件。  
3. 接入 `suite_chrome` + `vscode_theme` + codicons；自建 `_ui` Token 与 chrome 配方。  
4. SharedSession + `run_action` + Context Next。  
5. 每页：空态 CTA、需要时的 next_step；无连接条副本、无 OUTPUT 副本。  
6. 英文 UI 字符串；源码 `plugins/<id>/` 热加载验证。  
7. 首个需求起走 PDCA×2；`tmp/pdca/` 留痕。  

---

## 12. 反模式速查（看见即改）

- 每页一条「总线 / 连接」第二标题栏  
- 侧栏又做文件 Recent，又做编辑导航  
- 空态只有文字，没有按钮  
- Context Next 永远停在同一步  
- 说明 Caption 吃掉半屏，Tooltip 空着  
- 双 Tab 条（活动内再套导航 Tab 条做 Scan|NMT 之类——应侧栏切视图）  
- 魔法宽高、列表永远出现无用横向滚动条  
- 为发版前预览去 `make_market` / 装 `.opk`  
- 代码里写中文  
- 一轮补丁宣布「需求完成」

## 13. 文档维护

- 本规范变更：随跨套件共识更新；业务专有流程写在各套件 `tmp/pdca/` 或领域设计文，**不**塞进本文件。  
- 与 `Suite_UI_UX_Design_System.md` 冲突时：以**更新、更严**的一方为准，并回写对齐。  
- Agent / 人类开发：开工前读本规范第 2、4、6、9、11 节；改 chrome 必对照第 4、12 节。
