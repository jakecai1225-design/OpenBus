# OpenBus 插件开发规范

> **地位：** 领域套件（`*-suite` / `*-studio`）后续开发的**总准则**。  
> **来源：** 从 CANopen Suite 等多轮 PDCA 中剥离的方法论、设计原则、UI/UX 与流程约定（不含具体业务协议细节）。  
> **配套：** [Suite_UI_UX_Design_System.md](Suite_UI_UX_Design_System.md)（视觉细则）· [Plugin_Domain_Suites.md](Plugin_Domain_Suites.md)（套件地图）· `.cursor/rules/ui-ux-philosophy.mdc` · `pdca-two-rounds.mdc` · `plugin-live-source.mdc` · `no-chinese-in-code.mdc`  
> **对标体验：** VS Code Light 工业 IDE 密度；**壳层强制四件套**（Activity · Side Bar · Editor Tabs · OUTPUT），见 §3。  
> **参考实现：** `canopen-suite` / `dbc-studio` / `eds-studio` / `uds-suite` / `obd-suite` / `j1939-suite`。

---

## 1. 产品定位

| 要 | 不要 |
|----|------|
| 一个领域 = 一个插件 = **一条龙应用** | 拆成十几个「单页工具」 |
| 共享会话（连接 / 选中 / 草稿 / 日志） | 每页各自一份连接条 / 日志副本 |
| 打开即可走完常用闭环 | 打开只看到设置或说明书 |
| 对标该领域独立软件的主路径 | 「功能齐全」但路径割裂 |

**一句话：** 插件是**应用**，不是对话框集合。

**产品面：** 只上架领域套件（`*-suite` / `*-studio`）与 AI Agent。多工具合集（TX Lab、Bus Security、Protocol Hub、Log Analysis、Bus Utilities）已退役至 `plugins/_retired/`，不得再作为独立产品入口出现在插件面板或市场。

## 2. 设计原则（必须遵守）

### 2.1 主工作面优先

- 主区域永远是**当前任务**（树 / 表 / 编辑器 / 波形），不是设置、说明或状态墙。
- 次要 chrome（侧栏、OUTPUT、状态、菜单）**安静、可收缩**，不得与内容抢注意力或高度。
- **一个水平 chrome 行**：不要叠标题栏 + 芯片条 + 第二套 Tab。

### 2.2 一条金路径（Foolproof primary path）

- 为该领域写清 **1～3 条黄金旅程**（如：打开 → 编辑 → 校验 → 应用 → 在线 → 导出）。
- 每条旅程：**空态 / 成功 / 阻塞** 都必须有 **1～2 个动词 CTA**（打开某页 / 执行某动作），禁止「只有一段灰字」。
- **Context Next（建议下一步）**：状态栏或文档区保留一个随会话推进的「下一步」按钮；不得在某一环永久卡住。

### 2.3 连续性（页连续 · 操作连续 · 过程连续）

- 选中对象、节点、文件路径在页间 **携带**（`set_focus` / 等价会话字段），不要让用户重选。
- 动作完成后给出**可见过桥**（next_step_bar、菜单、或 Context Next），而不是只写日志。
- 文件类能力进 **File 菜单**；编辑叶子进侧栏——**侧栏不做文件浏览器**。

### 2.4 信息架构克制

- Activity（活动栏）只放 **大工作区**（通常 ≤ 4～5 个）。日志不是活动页。
- 侧栏叶子：**一叶一事**；发现定位重复则合并或降级到 View / Device 菜单。
- 同域「文件层」与「总线层」能力若易混淆，用文案与入口隔离（例：文件映射 vs 在线映射），侧栏只保留主路径。

### 2.5 少而准，而非全而吵

- 能力可以深，但**默认露出**只保留主路径；高级入口进菜单 / 折叠 / 隐藏状态即可。
- 禁止为「完整性」增加第二工具条、说明行、嵌套卡片。

## 3. 壳层与导航（Workbench）— VS Code 四件套（强制）

> **产品对标：** VS Code Light 工作台。领域套件**必须**具备下列四件套，禁止「有的套件有、有的没有」。  
> **共享实现：** `plugins/_shared/suite_chrome.py` · `suite_tabs.py` · `suite_ui.py` · `vscode_theme.py` · `codicons`

### 3.1 标准骨架

```
Activity bar（左窄条 · 大工作区 ≤5）
  └─ Side Bar（该工作区叶子 · Ctrl+B · 默认可见）
  └─ Editor chrome 行（可关闭 Tab 驻留 · 布局开关）
       └─ 当前页内容（tool_strip → 工作面）
  └─ OUTPUT 底栏（一排工具 + 列表 · Ctrl+J · 默认可见）
  └─ 状态栏（路径 / 脏标 / 会话摘要 / Context Next）
```

对比 VS Code：

| VS Code | OpenBus 套件 | 强制？ |
|---------|--------------|--------|
| Activity Bar | `NAV_PAGES` + Activity 图标条 | **必有** |
| Side Bar | `side_bar_enabled=True` + `workspace_sidebar` 叶子 | **必有** |
| Editor Tabs | `_open_tabs` + `suite_tabs.mount_editor_tabs` | **必有** |
| Panel（OUTPUT） | `panel_title="OUTPUT"` + `panel_tools` / `panel_body` | **必有** |
| Status Bar | `plugin_shell.attach_status_bar` + Context Next | **必有** |
| Menu Bar | File · Edit · View · Help（+ 领域菜单） | **必有** |

### 3.2 四件套规则（一条一条）

| 元素 | 规则 |
|------|------|
| **Activity** | 只放大工作区，**≤ 4～5**；日志不是 Activity；图标用 `codicons` |
| **Side Bar** | `build_workbench(..., side_bar_enabled=True, side_bar_visible=True, lock_activity=True)`；每 Activity 一份侧栏；**一叶一事**；叶子点击 → **开 Tab**（不是只换栈） |
| **Editor Tabs** | 侧栏叶子 / `goto_page` / `run_action(...goto...)` 一律 `_open_feature_tab`；可关闭；关光最后一个必须 reopen 该工作区**默认叶子**；实现 `_on_workbench_page`，禁止 `set_editor_title` 清掉 Tab（见 §13.1） |
| **OUTPUT** | 壳层唯一底栏；Pause / Export / Clear 一排工具；**禁止** Log 活动页、禁止每页再挂一份日志 |
| **快捷键** | Ctrl+B 侧栏 · Ctrl+J OUTPUT · Ctrl+1…N 切 Activity；默认侧栏与 OUTPUT **可见** |
| **连接 / 总线** | 仅 Setup（或薄状态栏）；**禁止**每页全宽连接条 |
| **菜单** | File（文档/工程/DBC/配置）· Edit · View（含 Toggle Side Bar / OUTPUT）· Help；领域菜单按需 |

### 3.3 实现清单（新套件 / 改造套件开工即勾）

```text
[ ] suite_chrome.build_workbench(..., side_bar_enabled=True, panel_visible=True)
[ ] workspace_sidebar.py：每 Activity 的叶子列表 + select_section
[ ] FEATURE_ROUTE / FEATURE_TITLES / _WORKSPACE_DEFAULT / _PAGE_ALIASES
[ ] _open_tabs + suite_tabs.mount_editor_tabs + _open_feature_tab / _close_feature_tab
[ ] _on_workbench_page / _on_activity_clicked（侧栏开 Tab，不清条）
[ ] OUTPUT：panel_tools + make_output_table（或等价）
[ ] pages/_ui.py → from _shared.suite_ui import *（密度与控件同源）
[ ] vscode_theme.apply / apply_*_chrome；英文 UI；tests/test_shell_routes.py
```

参考实现（壳层已对齐）：`canopen-suite`、`dbc-studio`、`eds-studio`、`uds-suite`、`obd-suite`、`j1939-suite`。

## 4. 页面 Chrome 配方（强制）

每一工作页统一为：

1. **`tool_strip` 或 `panel_header`** — 一行，高度 = `TOOL_H`（36）  
2. 可选 **`inline_filter`** — 高度 = `FILTER_H`（= `TOOL_H`）  
3. **工作面**（树 / 表 / 表单 / 分栏）— `stretch`  
4. 可选 **`next_step_bar` / `empty_state`** — 仅在需要时出现  

**禁止：**

- 标题下再挂一排说明 Caption  
- 双层工具条  
- 嵌套卡片、厚分隔、抢戏的状态大字  

**提示放 Tooltip**，不放占垂直空间的 Hint 行。

### 4.1 密度 Token（强制同源：`plugins/_shared/suite_ui.py`）

各套件 `pages/_ui.py` **优先** `from _shared.suite_ui import *`（或显式 re-export），禁止自研第三套魔法高度。

| Token | 建议值 | 用途 |
|-------|--------|------|
| `CTRL_H` | 28 | 按钮 / 输入 / 下拉 |
| `STRIP_PAD_V` | 4 | 工具条 / 过滤条上下内边距 |
| `TOOL_H` | `CTRL_H + 2×STRIP_PAD_V`（**36**） | 工具条 / 面板头 |
| `FILTER_H` | **= `TOOL_H`** | 过滤条（与工具条同高，禁止更矮） |
| `ICON` / `ICON_TOOL` | 16 | 按钮 / 图标钮 |
| `ROW_H` | 26 | 列表行（防 Win DPI 裁切） |
| `PAD_X` / `GAP` | 10 / 6 | 边距与间距 |
| `PANE_MIN` / `PANE_MIN_PROP` | 180 / 200 | 分栏下限，保证可拖 |

**硬约束：** `TOOL_H` / `FILTER_H` ≥ `CTRL_H + 2×STRIP_PAD_V`。更矮会导致 `QLineEdit` / `QComboBox` **底边框被裁切**（见 §13.6）。  
`tool_strip` / `inline_filter` 禁止再对 strip 容器设 `max-height` 钳死在 32。  
页面内**禁止魔法高度**；一律引用 Token。

### 4.2 分栏

- 使用共享 `configure_splitter`：**不透明实时改宽**（两侧一起变宽，禁止「一页盖住另一页」）。  
- 主工作面 : 属性/目录 ≈ 黄金分割；主面在左或右按任务定，但须一致。  
- `ScrollBarAsNeeded` + 长文 `ElideRight`；目录类列表横向滚动条默认关闭。

## 6. 会话、命令与互操作

### 6.1 SharedSession（或等价）

套件内单一会话对象，至少承载：

- 当前文档 / 工程路径与脏标记  
- 共享业务选择（节点、焦点索引等）  
- 草稿 vs 已应用数据（若存在两层）  
- 日志回调、帧/事件订阅  

跨页读会话，**不要**用页面局部全局变量硬传。

### 6.2 `run_action` 命令总线

菜单、空态、Context Next、页内按钮统一走：

```text
run_action("domain.verb", **kwargs)
```

新增能力先登记 handler，再挂 UI。禁止页内直接「只改自己、不通知壳」。

### 6.3 焦点携带

- 树/表选中 → `document.set_focus` / `session.set_focus`（或等价）  
- 焦点变化应 **`on_focus` 通知**（不必等同 `on_changed` / dirty）  
- 目标页打开或激活时消费焦点并高亮/填充；提供 `goto_*_target` 类跳转  
- Context Next / next_step / 右键菜单应能带着上下文跳转（见 §13.2）  

### 6.4 Context Next 启发式

确定性阶段机即可，例如：无文档 → 保存 → 校验 → 应用 → 在线观察 → 导出。  
每执行一次建议动作应能**推进阶段**，避免死循环在同一步。

## 7. 文件、工程与侧栏分工

| 能力 | 归属 |
|------|------|
| New / Open / Save / Recent / 工程内文件列表 | **File 菜单** |
| 编辑叶子（对象、映射、校验、配置视图…） | **侧栏** |
| 电源级在线视图（若侧栏已饱和） | Device / View 菜单 |
| 首屏引导 | 空态 CTA + Context Next；**不要**第五个「开始」Activity |

工程多文档：列表与「主文件」标记放 File 子菜单或工程对话框；侧栏保持编辑导航干净。

## 9. 质量门禁：PDCA × 2

**任何产品需求不得「改一版即结案」。** 必须两轮完整 PDCA：

1. **P** Plan：缺口、目标、验收、风险、Out of scope  
2. **D** Do：只实现 Plan 所列  
3. **C** Check（分文件）：Test · UX（对照本规范 + 金路径）· Accept  
4. **A** Act：保留 / 修复 / 丢弃 → 喂给 Round 2；Round 2 Accept 通过才 **CLOSED**

临时文档目录：`tmp/pdca/<suite>-<feature>/`（`STATUS.md`、`R{n}-P|D|C-*|A-*.md`）。

质量条：顶级密度、chrome 纪律、主路径傻瓜化；逻辑单测 + 关键 UI 契约测试；禁止静默回退。

## 11. 新套件开工清单

1. 写清领域金路径（≤3）与对标边界（做 / 不做）。  
2. **先落地 §3 VS Code 四件套**（勾完 §3.3 清单再写业务页）。  
3. Activity ≤ 5；侧栏叶子无重复；File 管文件；Log ≠ Activity。  
4. `suite_chrome` + `suite_tabs` + `pages/_ui` → `suite_ui` + `vscode_theme` + codicons。  
5. SharedSession + `run_action` + Context Next；持久化 `open_tabs`。  
6. 每页：`tool_strip` / 空态 CTA；无连接条副本、无 OUTPUT 副本。  
7. 英文 UI；源码 `plugins/<id>/` 热加载验证。  
8. 首个需求起走 PDCA×2；`tmp/pdca/` 留痕；R1 Accept 含四件套全绿。

## 12. 反模式速查（看见即改）

- **缺 Side Bar**（`side_bar_enabled` 未开，或 Activity 直接换整页无叶子导航）  
- **缺 Editor Tabs**（侧栏只 `set_editor_title` / 换栈，叶子不能多开、不能关）  
- **缺 OUTPUT 底栏**或把 Log 做成 Activity  
- 有的套件四件齐全、有的套件半套壳（产品面风格不统一）  
- 每页一条「总线 / 连接」第二标题栏  
- 侧栏又做文件 Recent，又做编辑导航  
- 空态只有文字，没有按钮  
- Context Next 永远停在同一步  
- 说明 Caption 吃掉半屏，Tooltip 空着  
- 双 Tab 条（活动内再套导航 Tab 条做 Scan\|NMT 之类——应侧栏切视图）  
- 侧栏叶子只 `set_editor_title` / 换栈，不驻留可关闭 Tab  
- 实现 Tab 却未挂 `_on_workbench_page`，导致点叶子 Tab 条被 `set_editor_title` 清掉  
- Activity > 5 且叶子全堆进活动栏（应压到 ≤5 柱 + 侧栏叶子）  
- Log / OUTPUT 做成活动页  
- 同域多页互不感知 focus；无搜索、无右键、无「回 Messages / Dictionary」过桥  
- Attributes / 定义类页只显示「已设置」值，不显示 Default / Type / Range / Source  
- 选中**信号**时 Values 空白：只列 `SG_` 定义、不展示父 Message 已设属性、也不注入 GenSig* 默认  
- `tool_strip` / `inline_filter` 行高 < 控件高 + 上下 padding → 输入框**缺底边**  
- Strip 容器 `max-height: 32`（或任何小于 `CTRL_H+2×pad` 的钳制）  
- 魔法宽高、列表永远出现无用横向滚动条  
- 各套件自研第三套 `_ui` Token，不跟 `suite_ui`  
- 为发版前预览去 `make_market` / 装 `.opk`  
- 只改 `plugins/` 或只改一份 `market.json`，市场 / 侧栏 / 发现仍露出已退役插件  
- 往产品面加回杂烩 Hub（TX Lab、Protocol Hub 等）  
- 代码里写中文  
- 一轮补丁宣布「需求完成」

## 13. 近期共性踩坑与强制对策（2026-09 收口）

下列条目来自 DBC Studio Tab / Attributes、CANopen 密度裁切、EDS Studio 规范改造、以及「杂烩插件退役」多轮返工。**以后同类改动必须一次对齐，禁止只改一处再靠用户截图纠错。**

参考壳层实现（四件套已对齐）：`canopen-suite`、`dbc-studio`、`eds-studio`、`uds-suite`、`obd-suite`、`j1939-suite`。

### 13.1 编辑器 Tab 驻留（侧栏 → 主窗）

| 踩坑 | 强制对策 |
|------|----------|
| 侧栏只换 `QStackedWidget` + `set_editor_title`，叶子无法多开、无法关闭 | 有子功能的工作区必须走同款：`_open_tabs` + `_mount_tab_bar` + `_open_feature_tab` / `_close_feature_tab`；`goto_page` / 侧栏 `on_select` 一律开 Tab |
| 点侧栏叶子后 **Tab 条消失**，点 Activity 才回来 | 根因：`suite_chrome.highlight_activity` → `_select_page` 在无 `_on_workbench_page` 时调用 `set_editor_title`，**清掉**已挂的 Tab。对策：① 套件实现 `_on_workbench_page`；② chrome 在已有 `_chrome_tabs` 时禁止标题覆盖；③ Activity 键列入 `tab_pages` 或等价白名单 |
| 关光最后一个 Tab | 必须 reopen 该工作区默认叶子（如 Messages / Dictionary），禁止空 chrome |
| 单叶工作区侧栏点了但**无 Tab、主区空白**（Scan / Batch / Security / Setup 等） | Activity id 与叶子 key **同名**时，禁止用 `if feature in _ACTIVITY_KEYS: return` 拒开 Tab。用 `_LEAF_KEYS = frozenset(FEATURE_TITLES)` + `_is_leaf_feature`；仅拒绝「纯 Activity」（如 `diagnose` 不在 titles）。`suite_tabs.normalize_open_tabs` 同理勿丢同名叶子 |
| 页内再挂 `chrome_tabs` 抢 chrome 行 | Dictionary\|Device、Starters\|Profiles 等**分段**留在页内（`SuiteSegmentTabs`），不要 `root.chrome_tabs` 挂进主窗 |

参考：`plugins/canopen-suite/app_shell.py`、`plugins/dbc-studio/app_shell.py`、`plugins/eds-studio/app_shell.py`；共享槽：`suite_chrome.set_editor_tabs`。

### 13.2 同域页间互操作（打通）

| 踩坑 | 强制对策 |
|------|----------|
| Messages / Value tables / Attributes（或 OD / Dictionary / PDO）各管各的选中 | Document / Session 提供 `set_focus` + **`on_focus` 通知**（焦点变了不必 `mark_dirty`）；目标页 `refresh` / `select_*` 消费焦点 |
| 「有数据但页是空的」 | 解析层与 UI 层都要打通：例 DBC 将内联 `VAL_` 提升进 `value_tables`；Attributes 展示 **Default / Type / Range / Source**，未覆盖时用默认作为生效值展示，并解析完整 `BA_DEF_` 对象类型（含 `EV_` / `*_REL_` 等） |
| 选中信号后 Attributes Values 全空 | OEM DBC 常只有 `BO_`/`GenMsg*`。信号目标必须同时列出：① 全部 `SG_` 定义 + 信号 `BA_`（含 **GenSig*** 内置默认）；② 父 Message **已设置**属性，Source=`message`，Apply 写回 `BO_` |
| 用户无法串联操作 | 列表/树 **搜索框**进顶栏 `tool_strip` 或 `inline_filter`；**右键菜单** + Related：`goto_editor_target` / `goto_attributes` / `goto_*`；Context Next 带着上下文跳转 |
| BA_ 帧 ID 对不上 | `BA_` 的 CAN ID 用 `int(mid, 0)`（支持 `0x50`），再 `& _ID_MASK` |

验收口诀：**选中一次，三处认得；搜得到、跳得回、改得完。**

### 13.3 产品面三处必须同改（市场 · 侧栏 · 插件发现）

退役、上架、改名插件时，**禁止**只动源码目录或只改仓库根 `market/market.json`。

| 表面 | 机制 | 必须同步 |
|------|------|----------|
| 插件发现 / 侧栏 Installed | `PluginManager::scanPluginsDirectory` | 跳过 `_` 前缀目录；`retiredPluginIds()` 黑名单；源码迁 `plugins/_retired/`；清 `build/bin/plugins/<id>` |
| 插件市场卡片 | `MarketIndex` 读 market.json | **白名单** `domainPluginAllowlist()`；过滤退役 id；改完后同步 **三份**索引：`market/market.json`、`build/market/market.json`、`build/bin/market/market.json`（运行时优先读后两者） |
| 打包 / 生成市场 | `plugin_tool.SUITE_IDS` + `make_market.SUITE_CATALOG` | 与 `src/core/plugin/domainplugins.h` **同一套** Keep / Retired；生成后默认写出 `build/bin/market` 并 copy 到 repo `market/` 与 `build/market/` |

单一事实源：

- C++：[`src/core/plugin/domainplugins.h`](../src/core/plugin/domainplugins.h)  
- Python：`scripts/plugin_tool.py` 中 `PRODUCT_SURFACE_IDS` / `RETIRED_IDS`  

`MarketModel` / `MarketTab` 展示层再滤一层退役 id，防止漏网。

**产品面 Keep：** `*-suite` / `*-studio` + `ai-agent`（+ 硬件驱动）。  
**禁止再上架的杂烩：** `tx-lab`、`bus-security`、`protocol-hub`、`log-analysis`、`bus-utilities`（源码仅存 `_retired/`）。

### 13.6 工具条 / 过滤条裁切输入框底边（密度）

| 踩坑 | 强制对策 |
|------|----------|
| `TOOL_H=32`、`FILTER_H=34`，布局上下各 pad 4，对 `CTRL_H=28` **算不过来** | `TOOL_H = FILTER_H = CTRL_H + 2×STRIP_PAD_V`（推荐 28+8=**36**）；`tool_strip` / `inline_filter` 边距用同一 `STRIP_PAD_V` |
| CSS `max-height: 32` 钳死 strip | **删除** strip 容器的 `max-height`；只留 `min-height` |
| 只给 `QLineEdit` 画边框，`QComboBox` 缺底边 | Strip 内 `QLineEdit` **与** `QComboBox` 同一套 `border: 1px solid` |
| 页内手写 `QHBoxLayout` + 矮 margins 塞 Combo | 一律走 `_ui.tool_strip` / `inline_filter`，禁止再发明第三种矮条 |

参考：`plugins/canopen-suite/pages/_ui.py`（`STRIP_PAD_V` / `test_strip_borders.py`）。各套件 `_ui` 应对齐同一不等式。
