## 3. Phase A：构建提速（详细步骤）

> 现状瓶颈（实测，见评估稿 §2.3）：链接 13 min（83%）+ core.a 重打包 9 min。A 阶段全部是构建脚本/工具链改动，**不触碰业务代码**。

### 3.1 A1 — Dev 构建档（主要收益来源）

**问题**：当前唯一档位是 Debug（全量 DWARF），172 MB exe 逼着 ld.bfd 每次全量重链 13 min。

**改动**：
1. `CMakeLists.txt`（根）在 `project()` 之后追加：
   ```cmake
   # Dev 档 — 日常开发：O1 + 行号级调试信息，链接体积/耗时数量级下降
   set(CMAKE_CXX_FLAGS_DEV "-O1 -g1")
   ```
2. `scripts/build.py`：
   - `BUILD_TYPES` 增加 `"Dev"`；
   - 新增全局参数 `--build-dir`（默认 `build`），所有子命令透传，允许 `build-dev/` 与 `build/`（全量 Debug）并存，避免切档全量重编。
3. 用法：
   ```
   python scripts/build.py configure --build-type Dev --build-dir build-dev
   python scripts/build.py build --build-dir build-dev -j8
   python scripts/build.py run   --build-dir build-dev
   ```

**验收**：Dev 全量构建 ≤ 5 min；改 1 个 ui 文件端到端 ≤ 3 min（A2/A4 后进一步降到 ≤ 90 s）。
**回退**：不配置 Dev 即回到现状，零影响。

### 3.2 A2 — 静态库 thin archive（消灭 9 min 重打包）

**问题**：`ar qc` 把全部对象文件复制进 .a（core ≈ 90 个对象 × 大体积调试信息 = 9 min）；改任何一个 core 文件都触发全量重打包。

**改动**：根 `CMakeLists.txt` 增加（仅 GNU/MinGW）：
```cmake
if(WIN32 AND CMAKE_CXX_COMPILER_ID STREQUAL "GNU")
    # thin archive：只记录对象路径不复制内容，重打包降为毫秒级。
    # 静态库仅供本构建树内部链接使用，不出库/不安装，thin 引用始终有效。
    set(CMAKE_CXX_ARCHIVE_CREATE "<CMAKE_AR> qcT <TARGET> <LINK_FLAGS> <OBJECTS>")
endif()
```
**验收**：`.ninja_log` 中 `libopenbus_core.a` 步骤从 ≈513 s 降到 < 1 s；链接产物正常。
**回退**：删除该 set() 即恢复。

### 3.3 A3 — ld.gold 链接 PoC（可选，成功才启用）

> **实测结论（2026-08-19）：否决。** MinGW 发行版自带的 ld.gold 为 ELF-only 构建，
> 链接 PE 目标时报 `--subsystem: unknown option`（exe）与
> `--enable-auto-image-base: unknown option`（驱动 DLL），开关已删除。
> A1+A2 的实测收益（ui 24.3 s / core 28.7 s / 全量 328 s）已超阶段目标，无需 gold。

**背景**：Qt MinGW 工具链自带 `ld.gold.exe`（已确认在 `C:/Qt/Tools/mingw1310_64/bin/`），未试用过。gold 对大体积调试信息的链接通常显著快于 bfd。

**步骤**：
1. 根 `CMakeLists.txt` 增加开关（默认关）：
   ```cmake
   option(TRY_GOLD "Use ld.gold for linking (Dev profile PoC)" OFF)
   if(TRY_GOLD)
       add_link_options(-fuse-ld=gold)
   endif()
   ```
2. Dev 档配置 `--build-dir build-gold` + `-DTRY_GOLD=ON`，全量构建。
3. **冒烟验证**（必须全过才算通过）：启动 → 依次打开 Trace / Graphic / 设备连接 / 插件市场标签 → 加载一个 DBC → 驱动列表可见 → 关闭重开一次。任何异常（崩溃/花屏/资源丢失）即判失败。
4. 通过：Dev 档默认启用 gold；Debug/Release 保持 ld.bfd（保守）。失败：删除开关，A1+A2 收益已足够。

### 3.4 A4 — Windows Defender 排除 + 基线度量

1. 管理员 PowerShell（一次性）：
   ```
   Add-MpPreference -ExclusionPath 'E:\code\sin\sin\build','E:\code\sin\sin\build-dev','C:\Qt\Tools\mingw1310_64','E:\code\sin\sin\tools'
   ```
2. 度量脚本 `scripts/measure_build.py`（新增，约 100 行）：对指定 build 目录依次执行
   - 场景① touch 一个 ui 文件 → 增量构建
   - 场景② touch 一个 core 文件 → 增量构建
   - 场景③ 全量 clean 构建
   解析 `.ninja_log` 输出各步骤耗时表，供前后对比留档（`doc/构建基线.md`）。

### 3.6 已否决项（沿用历史结论，本轮不再尝试）

| 项 | 结论 | 出处 |
| --- | --- | --- |
| LLD 链接器 | 在本机 Windows 上产出损坏的可执行文件 | 根 CMakeLists.txt 注释（曾尝试） |
| ccache | 与 MinGW g++ 13 的 PCH 存在静默缓存失效（数据不命中），收益不可靠 | 根 CMakeLists.txt 注释 |
| `-ffunction-sections -Wl,--gc-sections` | 可能误删仅被插件/元对象系统引用的段，风险 > 收益 | 评估结论 |

## 4. Phase B：业务 DLL 化（详细设计）

### 4.1 目标二进制结构

```
build/bin/
├── openbus.exe            薄壳：main + mainwindow 装配 + activitybar/bottompanel/
│                          rightpanel/spliteditorarea/sidebarpanels/settingsdialog
├── openbus_data.dll       公共底座 = 现在的 openbus_core + models + utils
│                          + thememanager（从 ui 迁入）
│                          全部 core 单例在此保持唯一实例
├── openbus_trace.dll      traceview/filterbar/filterheaderview/columnfilterpopup/
│                          tracediffwidget/tracestatisticswidget/colorruleeditor
├── openbus_graphic.dll    graphicview/graphic/downsample/signalconfigdialog/datawindow
├── openbus_transceive.dll signalsendtab/playbacktab/offlineanalysistab/recordtab
├── openbus_dbc.dll        dbcdetailtab/dbcimportdialog/tools/dbcsignallistview
├── openbus_flow.dll       measurementsetupview/deviceconnectiontab
├── openbus_market.dll     markettab/marketmodel
└── drivers/<id>/…         既有驱动插件，不动
```

### 4.2 模块接口（放在 `core/module/`，随 openbus_data.dll 导出）

```cpp
// src/core/module/imodule.h
#include <QWidget>
#include <QIcon>
#include <QString>

// 业务模块上下文 — 壳提供的全部服务入口（避免业务依赖壳的具体类型）
struct ShellContext {
    QWidget *mainWindow = nullptr;      // 供对话框 parent
    // 其余按迁移需要逐步增加（状态栏消息、底部输出等），接口只增不改
};

// 业务模块接口 — 只依赖 Qt 基础类型与 data 层类型，禁止依赖壳类型
class IBusinessModule {
public:
    virtual ~IBusinessModule() = default;
    virtual QString id() const = 0;        // "trace" / "graphic" / ...
    virtual QString title() const = 0;     // 标签默认标题
    virtual QIcon icon() const = 0;
    virtual QWidget *createWidget(ShellContext &ctx) = 0;  // 标签页内容
};

// 每个业务 DLL 唯一导出的符号（C 接口，零 ABI 面）
// extern "C" OPENBUS_MODULE_API IBusinessModule *openbus_createModule();
```

```cpp
// src/core/module/moduleregistry.h — 壳在 main() 里显式注册各 DLL 工厂
class ModuleRegistry {
public:
    static ModuleRegistry *instance();
    void registerModule(const QString &id, IBusinessModule *(*factory)());
    IBusinessModule *module(const QString &id) const;
    QStringList ids() const;
};
```

**关键设计决策**：
1. **业务 DLL 只导出一个 C 工厂函数**（MinGW 默认全符号导出，无需逐类 export 宏；显式导出硬化列为后续可选项）。模块内部所有类均为 DLL 私有。
2. **core 必须先变成 openbus_data.dll**：业务 DLL 链接静态 core 会导致每个 DLL 内嵌一份单例（DbcManager/AppConfig/ThemeManager 各自独立 → 数据错乱）。DLL 化后全进程共享唯一实例。这也是驱动插件"源码内嵌后端"做法（每驱动自带副本，插件自包含）与业务模块（必须共享状态）的本质区别。
3. **thememanager 迁入 data**：所有业务 DLL 都依赖 ThemeManager/QSS；它必须与单例们同住 data.dll（当前位于 ui/ 目录但只依赖 utils，迁移无阻碍）。
4. **resources.qrc 留在壳**：同进程内 `:/icons/...` 全局可见，各 DLL 无需自带资源。
5. **ShellContext 只增不改**：业务模块对壳服务的全部诉求走该结构，避免双向依赖；壳类型（SplitEditorArea 等）不出现在接口头。

### 4.3 文件 → 模块分配总表（src/ui 全部 68 个文件）

| 目标 | 文件 | 依据（依赖实测） |
| --- | --- | --- |
| **data.dll**（自 ui 迁出） | thememanager.{h,cpp} | 被全部业务使用；仅依赖 utils/svg_icon |
| **trace.dll** | traceview、filterbar、filterheaderview、columnfilterpopup、tracediffwidget、tracestatisticswidget、colorruleeditor | 簇内互引（traceview→filter* 等），对外仅依赖 data（core/models/utils/thememanager） |
| **graphic.dll** | graphicview、graphic/downsample、signalconfigdialog、datawindow | graphicview→signalconfigdialog、downsample；datawindow→signalconfigdialog+dbcmanager（信号数据窗，归 graphic） |
| **transceive.dll** | signalsendtab、playbacktab、offlineanalysistab、recordtab | 零簇间依赖（recordtab 连本地头都不含） |
| **dbc.dll** | dbcdetailtab、dbcimportdialog、tools/dbcsignallistview | 仅依赖 core/dbcmanager、dbcdata |
| **flow.dll** | measurementsetupview、deviceconnectiontab | 仅依赖 data（thememanager/svg_icon/candevicemanager） |
| **market.dll** | markettab、marketmodel | 仅依赖 core/driver、plugin、thememanager |
| **exe（壳）** | main、mainwindow、activitybar、bottompanel、rightpanel、spliteditorarea、panels/sidebarpanels、settingsdialog | 壳装配件，仅依赖 data |

**两处既有簇间耦合及其解法**（迁移时处理）：
- `panels/sidebarpanels.h → ui/marketmodel.h`、`sidebarpanels.cpp → ui/graphicview.h`：侧边栏面板改为经 `ModuleRegistry` 取模块/经 data 层接口（marketmodel 的数据源 core/driver/marketindex 本就在 data；面板不再直接 include 业务视图头）。
- `mainwindow.cpp → 全部视图头`：这正是要消除的；按模块迁移节奏逐个替换为 `registry->module("trace")->createWidget(ctx)` 等。

### 4.5 mainwindow 瘦身路径（3,067 → ≤ 800 行）

1. 随各模块 DLL 化，`setupTraceTab/setupGraphicTab/...` 等按标签装配代码迁入对应模块（模块自己连接自己的信号槽）。
2. 标签页通用逻辑（打开/关闭/切换同步侧栏与活动栏）收敛为 `SplitEditorArea + ModuleRegistry` 的通用路径。
3. 菜单/工具栏 QAction 中业务专属动作（导入 DBC、新建 Trace 等）改为由模块注册进统一 ActionPool，mainwindow 只做装配。
4. 剩余职责：窗口骨架、dock 装配、状态栏、全局快捷键 → 目标 ≤ 800 行。

## 6. 风险与回退

| 风险 | 概率 | 缓解 / 回退 |
| --- | --- | --- |
| gold 链接异常（LLD 前车之鉴） | 中 | §3.3 强制冒烟清单；失败即弃用，A1+A2 仍达成主要收益 |
| thin archive 与后续工具链/安装规则冲突 | 低 | 静态库仅构建树内部使用；出问题删两行即回退 |

| 接口设计返工（ShellContext 不够用） | 中 | B0 先用一个模块验证接口；上下文结构只增不改 |
| AUTOMOC/PCH 跨 DLL 配置问题 | 低 | 每模块复制现有 PCH 清单；drivers 已验证 Qt DLL 化路线 |
