- 触发条件：zlg 插件 sha256 校验通过 **且** 本机插有真实 ZLG 设备（本机

- 现象（间歇）：枚举链堆损坏崩溃。gdb 栈：

- UB 特征：在 zlg 插件加 8 行诊断代码重新编译后崩溃消失，同场景跨 DLL 枚举
  数据完好（3 设备 name/type/ch 全部正常）——典型的内存时序/越界问题
- **第二轮防御性修复**（`candevice_zlg.cpp::enumerate()`，三层收窄无文档
  保证的行为）：
  1. 探测类型表收缩至 zlgcan.dll 明确支持的 FD/E-U 系列 7 型

     zlgcan.dll 传 ControlCAN 生态老型号（USBCAN-1/2）的无文档探测，
     为真机在场堆越界写的头号嫌疑；
  2. 移除 isOnline 探测（ZCAN_GetDeviceInf 对未打开句柄的行为同样无文档
     保证）；
  3. 枚举循环内不再构造 CanDeviceZLG 临时对象（deviceName 换静态查表
     typeName），缩小 push_back 表达式内的对象活动面。

  整体删除），MainWindow 构造真实走 DriverRegistry 初始化 + 设备枚举链，
  8/8 套件全绿。**待办**：真机在场 ×10 连跑复验（间歇性缺陷多轮验证，

### 3.7 DEF-07 DLL 宿主退出 loader lock 崩溃（P1，已修，C）
- 模块：`src/core/plugin/pluginmanager.cpp`
- 现象：DLL 宿主（含测试）退出时崩溃。gdb 栈：

  ~PluginManager → ~PluginHost（pluginhost.cpp:21）→ stop() → sendNotification →

### 3.8 DEF-08 跨 DLL PMF connect 断连群 45 处（P1，已修，C；第二轮）
- 模块：全局（UI 壳 → libopenbus_data.dll 的全部信号连接）
- 现象：`QObject::connect: signal not found in X` 运行时警告 49 处 / 13 类：
  ThemeManager、PluginManager、DbcManager、Player、BookmarkManager、
  CanDeviceManager、DriverRegistry、Recorder、MarketIndex、
  CanTraceProxyModel、CanTraceModel、CanSimulator、ViewportProxyModel
- 根因：类定义于 libopenbus_data.dll、connect 调用点在 openbus_ui 静态库
  （链入 exe）或模块 DLL 时，MinGW 下 PMF（成员函数指针）信号元方法
  解析（IndexOfMethod 地址比较）拿到本地跳转 thunk 地址 ≠ DLL 内 moc
  真实地址，连接静默失败。全库 grep 验证无 SIGNAL() 字符串 connect，
  即**主程序同结构同断**——主题切换、插件消息、回放进度、DBC 加载、
  设备状态、录制等 UI 联动实际全部失效
- 探索记录（第二轮）：首版「字符串 SIGNAL + PMF/lambda 槽」混搭不可行
  ——Qt 6 字符串重载只接受 SLOT() 字符串槽或声明为 slot 的成员，编译
  期即报 no matching function
- **第二轮修复**（13 文件 47 处调用点 + 配套）：
  1. 信号端全部改 `SIGNAL()` 字符串（运行期签名匹配不走 PMF 解析）；
  2. PMF 槽改 `SLOT()` 字符串；5 个原普通方法移入 slots 区
     （MainWindow::refreshWindowButtonIcons、ActivityBar::refreshIcons、
     MarketTab::refreshInstalled、DevicePanel::refreshDevices、
     ExtensionsPanel::refreshEntries）；
  3. lambda 槽统一经新增桥接类 **SignalRelay**（`src/core/signalrelay.h/.cpp`，
     编入 openbus_data 单一副本）转发：字符串信号 → SLOT(fire()) →
     std::function，覆盖 fire()/fire(QString)/fire(bool) 等常用签名；
  4. 生命周期：relay 以接收者（this/控件）为 parent，随接收者销毁自动断开。
- 验收：①新二进制 ui_offscreen 运行 "signal not found" 警告 49 处 → **0**；
  ②themeSwitchSurvives 等用例全绿；③新增启动无 connect 警告断言入
  initTestCase（永久回归防线）；④主程序 openbus.exe 待 rebuild 后
  按同口径人工确认（L3 第 6 项主题切换联动）。

### 6.3 过程教训（沉淀）
1. **时间线核对**：首轮验证曾误判"警告未清零"——ui_result.txt (17:02) 系
   旧二进制产物，新 exe 链接完成于 18:15。验证类操作必须核对产物与
   被测二进制的时间先后；
2. **Qt 字符串 connect 约束**：SIGNAL() 字符串重载不接受 lambda/PMF 槽
   （编译期报错而非运行期降级）——lambda 场景需 SignalRelay 类桥接，
   该模式已固化为库内通用组件；
3. **AUTOMOC 边界**：被多 target include 的 QObject 头文件不会自动生成
   moc（vtable 未定义链接错）——Q_OBJECT 头必须编入具体 target 的
   sources（signalrelay 编入 SRC_CORE）。
