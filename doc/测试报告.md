### 3.6 DEF-06 ZLG 外置驱动枚举堆损坏（P0/P1，**未修**，C）
- 模块：`drivers/zlg`（zlg_driver_plugin.dll）× `src/core/driver/driverregistry.cpp`
- 触发条件：zlg 插件 sha256 校验通过 **且** 本机插有真实 ZLG 设备（本机
  type=41/42/43 三设备在场）
- 现象（间歇）：枚举链堆损坏崩溃。gdb 栈：
  `DevicePanel::populateTree → ICanDevice::enumerateAll →
  DriverRegistry::enumerateDevices（driverregistry.cpp:338 外置分支 push_back）→
  _M_realloc_insert → DeviceInfo 拷贝构造（candevice.h:50）→ QString 拷贝 →
  QArrayData::ref(this=0x10)`；堆内存中毒模式 0xFEEEFEEE / 0xBAADF00D
- UB 特征：在 zlg 插件加 8 行诊断代码重新编译后崩溃消失，同场景跨 DLL 枚举
  数据完好（3 设备 name/type/ch 全部正常）——典型的内存时序/越界问题
- 测试规避：test_ui_offscreen 经 `DriverRegistry::setDriverEnabled("zlg", false)`
  禁用（disabled.json 备份还原），套件不依赖硬件环境
- **修复建议**：
  1. 开启 gflags FullPageHeap（或 ASan 构建）复现，捕获首次越界写；
  2. 审查 `src/core/candevice_zlg.cpp::enumerate()`（704-770）：DeviceInfo
     vector 增长路径、`CanDeviceZLG(e.type).deviceName()`（762 行临时对象
     构造/析构在 push_back 表达式内的求值顺序）、sharedZlgDll 函数级
     static 的初始化时序；
  3. 修复验收：恢复 zlg 启用 + 真机在场，`build.py test` 8/8 全绿 ×10 连跑
     （间歇性需多轮验证）。

### 3.7 DEF-07 DLL 宿主退出 loader lock 崩溃（P1，已修，C）
- 模块：`src/core/plugin/pluginmanager.cpp`
- 现象：DLL 宿主（含测试）退出时崩溃。gdb 栈：
  `libopenbus_data.dll DllMain → _execute_onexit_table → 静态析构 →
  ~PluginManager → ~PluginHost（pluginhost.cpp:21）→ stop() → sendNotification →
  QProcess::writeData → QWindowsPipeWriter 构造 → CreateThreadpoolWait` 崩
  ——Windows loader lock 下创建线程池对象
- 修复：单例有意泄漏（`instance()` 改 `static PluginManager *inst = new ...`）
  + qApp aboutToQuit 优雅关闭（startHostIfNeeded 内 connect）
- 影响面：主 exe 不受影响（atexit 非 DllMain 上下文）；所有 DLL 加载宿主受益

### 3.8 DEF-08 跨 DLL PMF connect 断连群 45 处（P1，**未修**，C）
- 模块：全局（UI 壳 → libopenbus_data.dll 的全部信号连接）
- 现象：`QObject::connect: signal not found in X` 警告共 45 处 / 13 类：
  ThemeManager×14、PluginManager×6、Player×4、DbcManager×3、DriverRegistry×3、
  CanDeviceManager×3、BookmarkManager×3、CanTraceProxyModel×2、MarketIndex×2、
  Recorder×2、ViewportProxyModel×1、CanTraceModel×1、CanSimulator×1
- 根因：类定义于 libopenbus_data.dll、connect 调用点在 openbus_ui 静态库
  （链入 exe）时，MinGW 下 PMF（成员函数指针）信号元方法解析失败。
  全库 grep 验证无 SIGNAL() 字符串 connect，即**主程序同结构同断**——
  主题切换、插件消息、回放进度、DBC 加载、设备状态、录制等 UI 联动
  实际全部失效
- 佐证：B6 实证字符串 QSignalSpy（SIGNAL() 宏）可跨 DLL 捕获 MarketIndex
  信号（test_market_driver 全绿）
- **修复建议**（二选一，前者改动小）：
  1. 上述 13 类 connect 全部改 SIGNAL()/SLOT() 字符串形式（运行期字符串
     匹配不走 PMF 解析）；字符串拼错的风险由编译期外部脚本或测试断言
     （QSignalSpy 字符串法）覆盖；
  2. 连接逻辑下沉：把 UI 壳内的 connect 迁入 data DLL 内部的装配代码；
  3. 修复验收：主程序启动后 grep 运行日志无 "signal not found" 警告，
     且 ThemeManager 切换、Player 进度条等联动人工确认生效。

### 3.9 DEF-09 onMeasurementToggled 未声明为 slot（P2，已修，C）

  "No such method"（flow 模块经直调不受影响，L2 无法驱动）
- 修复：移入 private slots 区（mainwindow.h:131，带注释）

### 3.10 DEF-10 FlowModule 两参 createPage 未覆写（P1，已修，C）
- 模块：`src/ui/flowmodule.h/.cpp` × `src/core/module/imodule.h`
- 现象与根因：`IBusinessModule` 有两个 createPage 重载——两参版
  （imodule.h:137）**默认实现返回 nullptr**；FlowModule 只覆写三参版。
  壳侧 `onOpenMeasurementSetup`（mainwindow.cpp:1866）与
  `onOpenDeviceTab` 无参分支（:767/:1814）调的是两参版 → 恒 nullptr →
  **Flow 测量配置页与设备连接页自 B4 拆分起打不开**；连锁：setup 页未
  创建 → `flowQuery("currentSource")` 返回空 → `onMeasurementToggled(true)`
  误判离线模式 → 无离线文件时弹 `QFileDialog::getOpenFileName`（offscreen
  下模态 exec 死等，UI-03 曾卡死 300s 超时）
- 诊断路径（供同类问题参考）：产品/测试代码内 qWarning 打点（`-o file,txt`
  文件输出防 stdout 管道缓冲丢失）二分定位：`[oms-3] mod=非空 → [oms-4]
  view=0x0` 锁定 createPage 返回 null
- 修复：FlowModule 补两参 override 转发三参版（flowmodule.cpp:58-63，
  头文件带 DEF-10 注释）；TransceiveModule 已有两参覆写不受影响
- 回归：UI-03 全绿（setup 页创建 → currentSource='hardware' → 硬件分支）
- 附注：`onMeasurementToggled` 在 setup 页不存在时默认走离线分支弹文件
  对话框的产品语义仍建议复核（当前修复消除了主路径触发，但极端时序
  下仍可能走到；建议 currentSource 查询为空时默认 hardware）

### 3.11 DEF-11 MainWindow 析构 destroyed 回调 UAF（P1，已修，C）
- 模块：`src/ui/mainwindow.cpp`
- 现象：L2 套件用例全部通过后**退出阶段 SegFault**（ctest 表现为 8/8 套件
  失败；手动跑退出码异常）。gdb 栈：
  `TraceTab::~TraceTab → QObject::destroyed → onOpenMeasurementSetup 内
  lambda（mainwindow.cpp:1917）→ m_traceInstances.remove("trace1") →
  QMapData::copyIfNotEquivalentTo → QString::begin(this=0xFEEEFEEE)` 崩
- 根因：`MainWindow::~MainWindow() = default`——基类 deleteChildren 阶段
  （删 TraceTab/GraphicView 等）派生类成员 m_traceInstances/
  m_graphicInstances **已析构完毕**，7 处 `connect(x, &QObject::destroyed,
  this, lambda)` 回调（1888/1916/1930/1954/2119/2163/1527）访问已释放的
  QMap 节点 → UAF。**主程序退出同样触发**（关窗 → MainWindow 析构）
- 修复：析构体（成员仍有效）显式断开实例 destroyed 回调
  （mainwindow.cpp:514-530，带 DEF-11 注释）；运行期标签页关闭路径
  widget 先亡、连接随对象消亡，不受影响

### 5.4 流程与基建建议
- **stdout 缓冲教训**（本轮多次误判来源）：崩溃/卡死进程的 stdout 含 Qt Test
  全部输出，管道全缓冲下会整批丢失；排查一律用 `-o file,txt` 文件输出
  （流式落盘）。建议在团队规范中固化；
- 构建统一走 `scripts/build.py`（增量/单目标同样），环境变量
  `SIN_CMAKE_DIR` + MinGW PATH 前置为必备前置步骤；
- CMake 测试目标（test_ui_offscreen）已含 Qt6Test.dll 与 offscreen 平台
  插件 POST_BUILD 部署，新增 Qt 组件测试时沿用该模式。
