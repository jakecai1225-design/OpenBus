## 1. 目标与验收口径

**目标**：
1. 干净 Windows 10/11 x64 机器（无 Qt、无 MinGW、无 Python、无任何开发环境）上，下载 → 解压/安装 → 双击运行，基础功能全部可用。
2. 一条命令产出可分发产物（`python scripts/package.py`），过程可重复、可留档。

**验收标准**（详见 §10 验证清单）：
- 干净虚拟机全功能冒烟通过（Trace / Graphic / 收发四页 / DBC / Flow / 插件市场 / 5 个内置插件）；
- 程序目录**只读可运行**（数据全部写 `%APPDATA%`，便携版可放 U 盘/任意目录）；
- 无缺失 DLL 弹窗、无“缺少运行库”提示；
- 安装包体积目标：**zip ≤ 60 MB**（含 Python）、安装器同量级。

**范围外**（延后）：macOS/Linux、自动更新（Sparkle/自研更新器）、代码签名证书采购、MSIX/商店上架。

### 2.2 关键源码事实（决定打包行为）

| 事实 | 出处 | 对打包的含义 |
| --- | --- | --- |
| 数据/配置/日志全部写 `%APPDATA%/openbus/`（settings.json、会话、日志） | appconfig.cpp / sessionmanager.cpp / logging.cpp / filterpresetmanager.cpp 均用 `QStandardPaths::AppDataLocation` | 程序目录只读即可运行 → **便携版天然可行**；卸载/升级不清用户数据 |
| 图标/QSS 等资源全部 qrc 内嵌进 exe | resources/resources.qrc | 无外置资源文件要管 |
| 插件发现：`<exeDir>/plugins/`，宿主脚本 `<exeDir>/scripts/sin_host.py`，SDK `<exeDir>/sdk/` | pluginmanager.cpp `findAppBaseDir()`（exe 目录优先，回退源码根） | 便携目录布局 = 源码树子集（plugins/ + scripts/ + sdk/ 随包） |
| Python 查找：`SIN_PYTHON` 环境变量 → python3/python/py，找不到仅告警 | pluginmanager.cpp `findPythonExecutable()` | 无 Python 主程序正常，仅插件不可用 → 捆绑后零缺口 |
| ZLG 驱动查找：`drivers/zlg/vendor/` → exe 目录 → `driver/` → ZCANPRO 安装目录 → PATH，且校验 64 位 PE | candevice_zlg.cpp `findZlgDllPath()` | 已支持 vendor 隔离布局，未来 .odp 驱动包可自带厂商运行时 |
| PEAK/Kvaser：QLibrary 动态加载 PCANUSB.dll / canlib32.dll | candevice_peak.cpp / candevice_kvaser.cpp | 缺失时该设备不可用、不崩溃（优雅降级） |
| slcan：Win32 API 串口（QueryDosDeviceW） | candevice_slcan.cpp | 无额外 Qt 模块/DLL 依赖 |
| market.json：本地 `market/market.json` 优先，否则远程占位 URL | marketindex.cpp `defaultMarketUrl()` | 市场页离线可用需随包带本地 market 目录（make_market.py 产物） |
| windeployqt 检测不到 qcustomplot（静态库）对 Qt6PrintSupport 的传递依赖 | build.py `cmd_deploy` 已手动补拷 | **打包脚本必须复用该逻辑**，否则缺 DLL |
| Qt 6.8 Windows 不自带字体，缺 lib/fonts 目录时 QFontDatabase 告警 | build.py 注释（O-2） | 打包时建目录；可再放开源字体 |

## 3. 分发形态选型

| 方案 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **1. 便携版 zip（主推）** | 解压任意目录即用 | 零安装、U 盘可携、工程师群体刚需、卸载=删目录 | 无开始菜单/文件关联；首次 SmartScreen 提示（未签名时） |
| **2. Inno Setup 安装器（正式分发）** | 单 setup.exe，向导式安装 | 免费、脚本简单（.iss 纯文本入库）、开始菜单/卸载/文件关联、可做驱动检测页 | 需要多维护一份脚本 |
| 3. NSIS | 同类安装器 | — | 脚本语法古老，无优势 |
| 4. Qt Installer Framework | Qt 官方 | 组件化安装 | 引入额外工具链，体积大，对本项目过重 |
| 5. MSIX | 商店化 | 沙箱干净 | 用户侧安装策略受限，工业现场常有策略禁用 |

**建议**：**双形态并存，同一套 staging 目录两种出口**。
- 工具软件（对标 CANoe/Wireshark 使用习惯）便携版是核心诉求；
- 正式对外发布/企业交付用 Inno Setup；
- 两者共享 §5 的打包流水线，仅最后一步不同（zip 打包 vs iscc 编译）。

## 4. 发布构建档与版本管理

1. **构建档**：发布用 `Release`（`-O2`、无调试信息）。当前日常 Dev/Debug 档**不用于发布**。`build.py` 已支持 `--build-type Release --build-dir build-rel`。
2. **版本号**：以根 CMakeLists `project(openbus VERSION x.y.z)` 为唯一事实源；打包脚本从 `CMakeCache`/`openbus --version` 读取（若暂无版本打印接口，读 CMakeCache.txt 的 `openbus_VERSION` 即可），产物命名：
   - `openbus-<ver>-win64-portable.zip`
   - `openbus-<ver>-win64-setup.exe`
3. **符号存档**：Release 档默认无 DWARF，崩溃回溯依赖日志（spdlog 已落盘 `%APPDATA%/openbus/logs`）。如需符号，可选 `RelWithDebInfo` + objcopy 分离（v2 再议，首版不做）。

## 5. 打包流水线设计 — `scripts/package.py`

新增独立脚本（不混入 build.py，职责分离），一条命令端到端：

```
python scripts/package.py [--version X.Y.Z] [--skip-installer]
```

**流水线步骤**（幂等，可重复执行）：

| 步 | 动作 | 要点 |
| --- | --- | --- |
| 1 | 配置并构建 Release（**全量**） | 复用 build.py（Qt/MinGW/CMake 路径逻辑），`build-rel/` 独立目录。必须全量（不带 --target）：driver_* 外置插件不在 openbus 依赖链上，只构主程序会得到空 drivers/（首轮实测踩坑）；构建后校验 5 驱动 .odp 布局完整 |
| 2 | windeployqt 部署 | `--release --no-translations --compiler-runtime`；**必须复用 build.py 的 Qt6PrintSupport 手动补拷逻辑**；随后按需只拷回 `translations/qtbase_zh_CN.*`（中文界面）；Qt6Test.dll 等全量构建副产物剔除 |
| 3 | 组装 staging 目录 `dist/stage/` | 从构建产物拷：exe + 业务 DLL + Qt/插件目录（drivers/ 不拷）；从源码树拷：`sdk/`、`scripts/{sin_host,driver_tool,plugin_tool}.py`；`driver/` 不拷（决策 7）；`market/` 作为离线安装源随包（决策 6） |
| 4 | 捆绑 Python 运行时 | 见 §6：本机安装版精简拷贝至 `stage/runtime/python/` + PyQt6 裁剪子集 + 自验证 import |
| 5 | 附加文件 | `THIRD_PARTY_NOTICES.md`（§9 许可清单）、`LICENSE.txt`（项目自身）、便携版说明 `README-PORTABLE.txt`（含市场安装引导） |
| 6 | **依赖完整性校验** | 对 staging 内每个 exe/dll/pyd 用 `objdump -p`（MinGW 自带）提取 import 表，逐一核对 DLL 均在 staging 内或系统白名单；缺一即 **FAIL**，防"漏拷只在用户机器上炸"。实测三轮收敛：首轮 22 缺失→白名单补系统 DLL（rpcrt4/shcore/wtsapi32/uiautomationcore/propsys/winhttp/winusb/authz/d3d9/d3d12/dwrite/imagehlp/icuuc 及老版 VC 运行库）+ kerneldlls 厂商 PE 排除 + PyQt6 补整套 VC 运行库与 imageformats 白名单→0 缺失（88 PE / 744 import） |
| 7 | 体积与内容报告 | 打印 staging 目录树 + 各部分体积，留档 `dist/package-report.txt` |
| 8a | 便携版出口 | zip `openbus-<ver>-win64-portable.zip`（ZIP_DEFLATED level 9） |
| 8b | 安装器出口 | `iscc installer/openbus.iss` → `openbus-<ver>-win64-setup.exe`（iscc 不在则跳过并提示，不阻塞便携版） |

**便携版 staging 目录布局**（最终形态，供评审确认）：

```
openbus/
├── openbus.exe
├── libopenbus_*.dll               # 业务 DLL（B5 后含 trace/graphic）
├── Qt6*.dll + platforms/ + imageformats/ + iconengines/ + styles/ + tls/ + networkinformation/
├── libgcc_s_seh-1.dll / libstdc++-6.dll / libwinpthread-1.dll
├── translations/qtbase_zh_CN.qm   # 仅保留中文
├── lib/fonts/                     # 字体目录（消 QFontDatabase 警告）
├── runtime/python/                # 捆绑的 Python 运行时（§6，含 PyQt6 裁剪子集）
├── scripts/                       # sin_host.py + driver_tool.py + plugin_tool.py
├── sdk/sin/                       # 插件开发 SDK（剔除 pycache）
├── market/                        # 本地市场索引（离线安装源：market.json + 3 .odp + 5 .opk + assets）
├── THIRD_PARTY_NOTICES.md
└── README-PORTABLE.txt
```

> 实施变更（决策 6/7）：`plugins/`、`drivers/` 不预装（用户从市场安装，首次安装时
> plugin_tool/driver_tool 自建目录）；`driver/`（ZLG 运行时）整体不随包。纯净启动下
> discoverPlugins 对不存在的 plugins/ 目录优雅跳过（仅 info 日志），findAppBaseDir
> 兕底返回 exe 目录，宿主脚本路径不受影响。

## 6. Python 运行时策略（关键决策）

**现状**：5 个内置插件全部是 Python `.opk`（main.py + plugin.json），由系统 Python 驱动 `sin_host.py` 宿主。无 Python 时插件页全灰 —— 与“下载即用”目标冲突。

**插件第三方依赖实测**（扫描各插件 import，2026-08-20）：

| 插件 | import 依赖 | 说明 |
| --- | --- | --- |
| blf-converter / bus-statistics / canopen-explorer / dbc-tool | 仅标准库（os/time/json/collections/sys/importlib）+ `sin` SDK | 零第三方包 |
| **uds-diagnostic** | 上述 + **PyQt6** | 唯一重依赖（UDS 客户端自绘 UI） |

> 注：plugin.json 目前**没有** dependencies 声明字段，依赖现状靠源码扫描得知 —— 建议为 plugin.json 增加 `pythonDeps` 字段（只增不改，与 ShellContext 同原则），让 package.py 能机读校验。

**选型**：

| 选项 | 说明 | 结论 |
| --- | --- | --- |
| A. 不捆绑，文档引导用户装 Python | 零体积 | ❌ 违背核心目标 |
| B. **捆绑运行时（已实施）** | 实施时未用 embeddable，改用**本机安装版精简拷贝**（含 `python314._pth` 隔离，效果等同）：解释器核心 + DLLs（剔 tkinter）+ Lib（剔 idlelib/tkinter/turtledemo/lib2to3/test/ensurepip 等），PyQt6 子集单建 site-packages。零网络依赖（embeddable zip 需下载），且标准库完整 | ✅ 开箱即用；PSF 许可允许再分发 |
| C. 捆绑完整 Python 安装器并静默装 | 侵入用户系统 | ❌ 违背便携原则 |

### 6.1 运行时定制要点（实施实录）

1. **findPythonExecutable 已落地**：候选列表最前插入 `<exeDir>/runtime/python/python.exe`（两处：主程序 pluginmanager.cpp 与市场页 runDriverTool 复用）；`SIN_PYTHON` 环境变量仍最高优先，便于用户替换自带解释器。
2. **`python314._pth` 隔离**（embeddable 同款机制）：忽略注册表/环境变量，路径全部相对 runtime 目录；含 `import site`（启用 site-packages）；**pip 不随包**（ensurepip/venv 均剔除，体积与合规考虑——插件市场安装 .opk 为纯文件拷贝，无需 pip）。
3. `__pycache__` 一律剔除（宿主首次运行自建）。
4. **降级语义不变**：捆绑 Python 仅供宿主使用，不污染系统 PATH、不写注册表 —— 用户机器装没装 Python 互不影响。
5. **版本锁定**：打包时生成 `runtime/python/Lib/site-packages/requirements-lock.txt`（PyQt6/PyQt6-Qt6/PyQt6-sip 精确版本）+ dist-info 元数据随包（importlib.metadata 可读）。

### 6.2 PyQt6 捆绑与裁剪（uds-diagnostic 专用）

PyQt6 完整 wheel ~150 MB（含一份 Qt 副本），必须裁剪后随包：

1. **只保留运行所需子集（已实施）**：`QtCore.pyd / QtGui.pyd / QtWidgets.pyd / QtSvg.pyd` + sip 绑定 + `Qt6/bin`（4 Qt DLL + **整套 VC 运行库**，实测 Qt6Core 引 msvcp140_1、QtGui.pyd 引 msvcp140_2，防 Qt 小版本引用漂移）+ `platforms/qwindows.dll` + styles/iconengines + imageformats 白名单（qgif/qico/qjpeg/qsvg，与 windeployqt 部署集对齐）。实测裁剪后 **43.1 MB**（含 dist-info 与 requirements-lock.txt）。
2. **不与主程序 Qt 共享 DLL**：PyQt6 wheel 携带的 Qt 与主程序 Qt 6.8.3 版本/补丁可能不同，Python 插件进程内加载失败难排查 —— 各带各的，体积代价换取确定性（裁剪后增量约 30~35 MB 未压缩）。
3. **版本锁定（已实施）**：打包时生成 `requirements-lock.txt` 随包留档（§6.1 要点 5）。
4. **回退方案**（若体积/稳定性不达预期）：uds-diagnostic 改用宿主侧 UI 能力（sin SDK 的 ui 模块已存在，见 sdk/sin/ui.py）重写自绘部分，彻底去掉 PyQt6 —— 属插件侧改造，超出本方案范围，列为备选。

## 7. 硬件厂商驱动的优雅降级（不捆绑，见 §0 决策 3）

厂商 SDK 授权通常**随硬件/官方驱动包分发**，我们不随包再分发 zlgcan.dll / PCANUSB.dll / canlib32.dll。缺件行为（源码已保证不崩溃）与增强手段：

| 缺失组件 | 现有行为（实测源码） | 打包后增强 |
| --- | --- | --- |
| zlgcan.dll | ZLG 设备不可用，日志告警 | 设备连接页/市场页展示“安装 ZCANPRO”引导链接（v1 用 README 说明替代） |
| PCANUSB.dll | PEAK 设备不可用 | 同上（PEAK 官网驱动） |
| canlib32.dll | Kvaser 设备不可用 | 同上（Kvaser CANlib） |
| 硬件不在场 | 驱动列表正常显示、连接报设备错误 | 不属于打包问题；冒烟验收覆盖“无硬件”路径 |

> 未来增强（非本方案范围）：.odp 驱动包的 `vendor/` 目录机制已就绪（findZlgDllPath 第一优先级），厂商运行时可由“市场页下载的驱动包”自带，实现免装 ZCANPRO —— 需逐厂商确认再分发授权后另行立项。

## 8. Inno Setup 安装器设计要点

`installer/openbus.iss` 入库（脚本即文档）：

1. **安装目录**：默认 `C:\Program Files\openbus\`，允许自定义；
2. **快捷方式**：开始菜单组（必选）、桌面图标（用户可选）；
3. **文件关联**（v2 再做）：`.sinproj` / `.sin` 关联 openbus.exe 图标与打开方式；
4. **卸载**：只删安装目录与快捷方式，**不动 `%APPDATA%\openbus`**，卸载确认页提示用户数据位置与手动清理方法；
5. **驱动检测页（可选增强）**：安装向导中检测 ZCANPRO / PCANUSB / canlib32 是否在系统（Inno Pascal 脚本 `FileExists`），仅在完成页展示提示清单，**不阻塞安装**；
6. **语言**：zh_cn + en 双语向导；
7. **升级**：覆盖安装允许（`useappwinid`/关闭运行中进程检查 —— 安装器检测 openbus.exe 运行则提示先退出）；
8. **签名**：无证书阶段跳过；取得证书后 `signtool` 接入 iscc 的 `SignTool` 指令（预留参数，不阻塞流程）。
